## Result

Implemented `server/src/SaveValidator.php` and `src/services/save-validator.ts` with
tests written and run before implementation. Both validate the unchanged shared
Draft2020-12 save schema with UUID format checks, then explicit version-specific
registry and relationship policy. All results are provisional. Nothing here reads,
writes, adopts, resets, migrates or acknowledges an account save.

The fixed wire cap is 262144 UTF-8 bytes; invalid UTF-8/JSON, lone escaped surrogates,
nonfinite numbers, non-object bodies, excess nesting, unknown fields and all schema
collection/text bounds fail without repair, truncation, default insertion or type
coercion. Notes use the schema's 4096 Unicode code-point limit, including astral
characters and combining sequences. Plain text containing markup is preserved as
text; this validator does not render it or strip content. Diagnostics contain only
fixed codes and field paths, never player text or submitted values.

Semantic checks include typed membership for all persisted references, authored
room/anchor and eligible-state agreement, E01/E02 safe Continue, explicit unsafe
world markers, duplicate inventory/recruit/UUID identities, legal item quantities,
recruit/ability/progress membership, active-party subset, hint/objective/level
relationships, completed-objective dependencies, rule-specific measurement
names/units/conclusions and current configuration/attempt freshness. Retained stale
measurements remain legal and are never repaired in place. Historical E03 is legal
in a safe snapshot; E03 shutdown and unsupported safe-state values are rejected.

Completed-objective expressions preserve every `all`/`any` branch. Only `always`
and `objective-complete` atoms are supported. The builder checks both metadata and
authored prerequisites; an unsupported nonmonotonic/item/flag condition fails policy
construction rather than being dropped from an alternative. Prior solutions are
not regraded from transient availability. This is bounded consistency validation,
not evidence that the server observed every historical action or that a player
proved independent technical understanding.

## Public API and integration requirements

- TypeScript: `new SaveValidator(policies)`. `validateStructure(bytes: Uint8Array)`
  performs bounded wire/schema validation; `validateNewWrite(bytes)` adds the
  selected content policy. Success is `{ok:true, provisional:true, candidate, json}`;
  `candidate` is recursively frozen and `json` retains the original decoded UTF-8
  text. Error is `{ok:false, provisional:true, code, path}`. Policy inputs are cloned
  and frozen. Exact request bytes remain the coordinator's fingerprint/retry input.
- PHP: `new NetworkQuest\SaveValidator(array $policies)` takes the same portable
  JSON policy represented as a list of `stdClass` objects. Both validation methods
  accept a raw byte string and return readonly `SaveValidationResult` with `ok`,
  `provisional`, `code`, `path`, and `candidateJson`. Success retains exact original
  bytes. `candidate()` returns a fresh decoded copy so a caller cannot mutate the
  retained validated payload. Failure exposes no candidate. Constructor failures
  indicate invalid/missing server-owned policy/schema, not a player semantic error.
- Fixed result codes: `body-too-large`, `json`, `schema`, `content-version`,
  `reference`, `safe-state`, `relationship`, `objective`, `measurement`. These are
  not HTTP responses. T043/T044 own response mapping and the existing fixed request
  guards. In particular, byte bounds apply before receipt lookup.
- **T043 must resolve the authorized account/key receipt before invoking current
  new-write validation, then reauthorize and recheck the receipt inside the final
  transaction before acting on either a candidate or a provisional error.** A
  retained exact operation can override a newly incompatible validation policy;
  no exception or early HTTP422 is emitted here. Current autosave/adoption, reviewed
  revision, receipt expiry, atomic persistence and concurrency remain T043 onward.
- `validateRuntime({game, activity})` is a separate client check. It requires an
  actual safe activity, projects only durable fields and applies the same validator.
  Dialogue/pending effect/transition/cutscene/encounter/fatal/shutdown/title cannot
  produce a candidate. The server cannot infer an omitted transient UI state from
  a client's `safeState` claim; server tests reject representable fixture markers.
  The actual safe-boundary/coordinator/UI wiring remains T048/T049/T051.
- These are **new-write-only** APIs. Unknown newer stored JSON is not forced through
  this validator before GET, rewritten, reset or migrated. T048/T144 own supported
  read/migration dispatch. Valid uppercase UUIDs are accepted and preserved in the
  payload. UUID duplicate/freshness identity comparisons are case-insensitive;
  qualified content IDs remain case-sensitive. T043 owns storage/adoption/key
  identity comparison without changing raw request fingerprint bytes.

## Registry and generation boundaries

`createSaveContentPolicy(registry, world, rules)` bridges an already validated actual
ContentRegistry to portable policy data for either runtime. The current accepted
world has 12 room metadata reservations and 11 authored records. Only R01/R02 have
authored room/anchor definitions; the bridge produces two save anchors, not twelve
playable rooms. Metadata-only current rooms, completed objectives and recruits fail.
Metadata character/prop/profile/objective identities can be notebook subjects,
without granting recruitment, inventory or objective completion. Current content
does not define achievements/caveats/recruit progression flags; the bridge does not
invent them. Explicit compatible authoring/policy work is needed as content grows.

Legal item maxima, measurement maps and unsafe marker values are explicit reviewed
`SavePolicyRules` inputs, not guessed from labels or prose. Missing measurement or
item policy fails closed when used. The test applies a declared PHY04 name/unit map
to an actual reducer-produced 105 m inspection and rejects a changed dBm unit.
No production policy file or production configuration is created by this task;
T043 integration must supply and review its selected policy. The additional shared
`tests/services/save-validator-policy.json` is clearly synthetic and does not add
fictional IDs to current content. Original T036 expectations were not edited.

The coordinator approved additional ownership of the portable synthetic test file,
`tools/generate-save-validator.ts` and the generated JS/type declaration pair. The
tool compiles Ajv only at build time, uses static ESM helper imports and emits no
runtime compiler/eval/Function constructor. A test regenerates and compares exact
artifacts. Rebuild with pinned Node and `node tools/generate-save-validator.ts
--generate`; invocation without `--generate` checks staleness. The unchanged package
scripts do not yet invoke this separate generator; its test checks staleness.

PHP loads the fixed bundled save contract and constructs Opis2.6.3 with no schema
resolver, preventing file/network schema retrieval. Formats remain enabled; default
mutation and filter/mapper/global/slot extensions are disabled. Packaging must include the contract at the
documented repository-relative location, or explicitly adapt that boundary later.
