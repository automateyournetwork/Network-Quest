## Reproduction and retained setup failures

Use the repository's pinned Node on PATH and set `NQ_PHP_BIN` to the pinned PHP executable. The PHP native proxy in a private checkout also needs `NQ_TEST_NODE_BIN` set to the absolute pinned Node executable. Run from a full checkout of the indicated checkpoint.

```sh
node tools/validate-content.ts
node tools/generate-save-content-policy.ts
node node_modules/vitest/vitest.mjs run --maxWorkers=2 \
  tests/content/{world-graph,endings}.test.ts \
  tests/state/{encounter-world,outcome-classification,autosave,spec001-migration-fixture}.test.ts \
  tests/services/save-coordinator.test.ts tests/ui/recovery-save.test.ts
node node_modules/vitest/vitest.mjs run --maxWorkers=2 \
  tests/content/registry.test.ts tests/state/{reducer,navigation,notebook,snapshot}.test.ts \
  tests/ui/{inventory,compendium}.test.ts
node tools/test-api.mjs --filter 'SaveConcurrencyTest|SaveRoutesTest|IdentitySecurityTest|AccountDeletionTest|AuthTransactionsTest|PreferencesRoutesTest|DeletionStatusRoutesTest'
npm run test:e2e -- --project=firefox-local-https --workers=2 \
  tests/e2e/{single-save,logout,account-deletion,migrations,outcomes}.spec.ts
```

The first PHP invocation finished 207 cases with two setup errors because the private copy lacked the proxy’s absolute Node path. Supplying `NQ_TEST_NODE_BIN` made both cases execute. The tests and expected results stayed fixed through both retries. The full Firefox command succeeded on its first attempt.
