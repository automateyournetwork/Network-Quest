## Concrete interfaces and behavior

`createResourcePool<T>(limits)` owns immutable resource specifications and explicit
leases. Keys identify a decoder/export/version; reusing a key with conflicting
loader, disposer or residency reservation is rejected. Shared loads deduplicate;
each owner releases independently. Limits bound entries (including queued work),
in-flight loads, prefetch leases, total leases and reserved decoded bytes. Current
work precedes queued prefetch. Capacity exhaustion fails honestly; there is no
unbounded hidden queue. Unowned ready resources form a bounded LRU cache, and
`trim()` disposes them explicitly.

Resource `bytes` is a conservative decoded-residency reservation. A returned size
above that reservation is rejected and disposed; these estimates are not compressed
download sizes or measured GPU memory. Cancellation does not free a still-running
loader's concurrency or byte reservation. A loader ignoring abort remains counted
until settlement; a late successful result is disposed exactly once. Failed loads
remove their entries and allow a new attempt. Rejecting loaders own cleanup of any
partially decoded intermediates. Disposal failures are counted while other cleanup
continues. `stats()` exposes actual entries/queue/leases/reservations/residency,
in-flight work and disposal failures. `createResourceScope` ties leases to an abort
signal and trims unused resources on owner disposal without destroying shared ones.

`createRoomAdapter` consumes a `RoomView` projection of T017's `AppShellView` plus a
room ID. It copies/freezes semantic inputs and supplies all actions, descriptions,
evidence and captions before visual preparation. Missing renderers, decode failures,
context loss, bounded-capacity failures and text mode preserve the same projection
and honest presentation status. Modes are `three`, `layered`, `sprite` and `text`,
with explicit detail and reduced-motion settings. No finished renderer or invented
room content is included.

Renderer `prepare` receives immutable view/settings, owned resources, an abort
signal, a restricted control-ID capture function and a context-loss callback.
Preparation must not attach visual content; `PreparedRoom.attach` runs only after
current-owner checks. The controller disposes stale completions and owned session
surfaces/listeners/animation callbacks through the renderer's disposal port.
Canceled preparations still count toward the pending-preparation limit until they
settle. Pause is applied before attachment, with another ownership check afterward.

The room adapter consumes the real restricted `ActionDispatcher`. T017 now exports
`ActionCapture` and `captureScope(expectedContext?)`. A fresh authoritative `show`
binds one epoch/context scope. Retry, mode changes and loading/ready/failure updates
retain that scope; `onView(view, capture)` must forward both arguments to
`AppShell.render(view, capture)`. Thus an old view cannot mint valid actions after
a same-version restore/invalidate. Each deferred renderer intent captures before
scheduling, dispatches the same bus-owned object on replay and is canceled on room
replacement/context loss/disposal. Unknown/unavailable controls are rejected. No
handler registration, direct state mutation, evaluator, effect or reward port is
given to the renderer. `onView(null)` requests owner cleanup at disposal.

`createAudioAdapter` owns bounded cues, voices and pending play attempts. Text is
required and retained in each cue state regardless of mute, hidden captions,
missing source, autoplay denial, corrupt media, skip, pause or completion.
`volumesFromSettings` maps the existing independent music/effects/voice settings;
volume changes validate atomically. `present` does not create/load/play media.
Initial `play` checks actual backend user activation, invokes native playback
synchronously within the permitted event and still handles browser policy denial.
Successful prior playback permits subsequent attempts, subject to browser policy.

Audio playback, media events and promises never dispatch gameplay actions. Skip
stops while retaining the transcript; explicit play replays. A cue's abort signal,
disposal or failed media removes listeners and releases its voice. Stale promise
completions/events cannot revive it. Canceled pending plays still count until
settlement. Suspending pauses audio; becoming visible leaves it paused for explicit
resume. This is an application hook, not T151's finished visibility wiring.
`createHtmlAudioBackend(document)` uses native optional media with `preload=none`,
browser activation, error/ended listeners, and source removal/load reset on
disposal. It introduces no runtime AI, dependency or decoded audio cache.
