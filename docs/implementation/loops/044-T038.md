## Session contract and API

`Sessions(Database, ?callable $clock = null, string $gamePath = ...)` uses trusted
server time by default. The clock injection is for deterministic tests, never an
HTTP input. The game path must be an explicit canonical routing path.

`bootstrap(?string $rawCookie): array` returns **internal** `context`, `csrfToken`
and optional `setCookie`. The context is a readonly `SessionContext` with id hash,
account ID, CSRF hash, generation, absolute expiry and authentication time. Never
JSON-serialize that context as a response. T041 must build the public schema with
only guest state/CSRF or the authenticated provider/display label, effective expiry,
independently revised preferences and current save summary. It must not disclose
provider subject, internal account ID, raw cookie or stored hashes.

The GET service inspects a valid stored session and updates its last activity.
It never creates an account, identity, preferences or save. A missing, unknown,
expired, malformed or ambiguous raw cookie becomes a fresh **guest** credential;
it never adopts the caller's supplied ID or selects one duplicate by position.
Guest status is not evidence of completed account deletion. A future route must
apply HTTPS, bounded headers and a reviewed source abuse control **before** guest
insertion; no uncontracted guest quota was invented in this task.

Cookies contain 32 bytes from `random_bytes`, encoded as canonical unpadded
base64url (43 characters). The exact header is `__Secure-nq_session=<opaque>;
Path=/arcade/play/network-quest/; Secure; HttpOnly; SameSite=Lax`. No Domain is
emitted, so it is host-only. No persistent browser lifetime is added. Path organizes
routing and is not a security boundary against other same-origin website scripts.
The raw Cookie field is parsed instead of PHP's name-normalizing `$_COOKIE`.
The service bounds it to8192 bytes before splitting, rejects duplicate game names
including identical values, malformed/quoted/noncanonical game tokens and header
controls. Valid unrelated cookies, including quoted cookie-octet values, coexist.

Only SHA-256 hashes of the cookie and CSRF token are stored. CSRF is a stable,
domain-separated HMAC-SHA256 output keyed by the decoded random cookie bytes.
This allows repeated GET session in separate tabs/service instances to recover
the same CSRF without persisting its raw value, a deployment secret or an extra
schema column. It is neither the cookie nor its stored hash. Exposing the CSRF
output does not provide the random HMAC key/cookie. Authentication replaces both.

`require(rawCookie, accountRequired=true, csrfToken=null): SessionContext` performs
request admission using the live DB every time. Null CSRF is reserved for reads
and OAuth callback state validation; ordinary mutations pass an actual value,
including empty for missing, through `Security::mutation`. Missing/expired/revoked
or guest-for-account requests fail401; wrong/missing session-bound CSRF fails403.
Rejected admission does not extend idle life. Two hours of inactivity and24 hours
from session creation are enforced at their exact boundaries independently of
cleanup. Activity does not extend the absolute deadline. A backwards clock also
fails closed. Missing or deleting accounts cannot authorize or inspect an account.

`within(PDO, priorContext, callback, accountRequired=true)` belongs inside the
owning Database's short `immediate` callback. It re-reads live session/account
status, both expiries, generation, bound account, CSRF hash, absolute expiry and
authentication time before invoking the callback. A prior context is not standalone
authorization. Save services must call this before final receipt lookup and before
returning a provisional semantic error or inspecting current revision/policy.
The callback receives the fresh context and may return its result. No provider IO,
expensive content validation or transaction-control SQL belongs inside it.

`rotateWithin(PDO, priorContext, verifiedAccountId)` is a trusted **internal**
provider-completion port. It requires a live initiating session and an existing
active account with identity/preferences rows; the caller must first verify the
provider, one-use state/session/purpose and account resolution. It generates new
cookie/CSRF, increments generation and removes the old session with all pending
auth transactions in one transaction. Rollback restores the old session/attempts.
It does not implement OAuth, create accounts or accept a browser account selector.

`revokeWithin(PDO, priorContext): string` removes only that session and its auth
attempts and returns an expired cookie with the same name/path/security attributes.
It preserves account preferences/save and other-device sessions. T046 must call it
only after the explicit logout choice and valid Origin/CSRF. The canceled client
warning makes no request. Network/commit failure must not be reported as logout.

The raw PDO and service arguments are trusted internal capabilities, not a sandbox
against hostile PHP code. The transaction guard rejects another connection and
calls outside a transaction; it cannot prove a hostile raw-PDO caller used the
owning helper or undo an intentional external commit. T045 must additionally honor
and reconcile its external deletion ledger before account access. `authTime` alone
never authorizes deletion: T036's ordinary-login rejection remains mandatory.
If T041 rotates during delete-reauth, it must preserve/create same-account,
purpose-bound completion evidence for the new session in the same transaction;
rotation intentionally cascades every old-session auth transaction.

## Request security contract and API

`Security(Database, exactHttpsOrigin, privateRateKey, ?clock)` takes explicit
operator inputs. The rate key must be at least32 cryptographically random bytes,
private and shared across workers. No key/configuration is discovered or logged.

- `headers(list<[name,value]>)` caps64 fields,128-byte names,8192-byte values and
  16384 total bytes; it rejects controls, malformed pairs/names and **all** duplicate
  names case-insensitively. Adapters must preserve duplicates before calling it.
  PHP/SAPI/web servers can coalesce or discard duplicates before PHP; equivalent
  rejection must be verified upstream. This helper cannot reconstruct lost fields.
- `mutation(normalizedHeaders, Sessions, accountRequired)` requires the byte-exact
  configured Origin then session-bound CSRF. No Referer, suffix, case-folding,
  wildcard, Host or forwarded-origin fallback is accepted. Callback GET uses the
  separately reviewed one-use provider state flow; deletion-status has its own port.
- `readBody(stream, normalizedHeaders, limit=262144)` reads at most limit+1 bytes
  and does not allocate/read according to Content-Length. It preserves exact bytes
  for receipt fingerprinting before current UTF-8/schema/content validation.
  Declared/actual overflow fails413; malformed or mismatching Content-Length,
  content encodings, CL+TE or unsupported/stacked transfer codings fail400.
  A single chunked transfer can use already-decoded SAPI bytes. Transport must
  separately enforce byte/header/slow-client bounds before buffering in PHP.
- `peerAddress(server)` uses only the trusted socket REMOTE_ADDR. Forwarded headers
  never select source identity. It validates IP syntax and canonicalizes IPv6 and
  IPv4-mapped IPv6. A production proxy needs an explicit reviewed trust adapter;
  using its shared socket address is conservative, not proof of end-user attribution.
- `limit(operation, admittedContext, trustedPeerAddress, receiptHash?)` implements
  delivery defaults with fixed UTC windows: save/preferences60/minute/account,
  deletion3/hour/account, auth-start5/10minutes/session plus30/10minutes/source,
  status30/minute/receipt plus60/minute/source. All dimensions are inspected and
  incremented atomically; a rejected dimension cannot partly consume another.
  A rejected request returns429 with positive bounded Retry-After through `problem`.
  This counter admission is not final account authorization; `Sessions::within`
  remains mandatory before protected final reads/writes.
- Buckets contain only keyed hashes, period, count and expiry. The hash binds the
  operation, dimension and time window, so raw addresses and stable cross-window
  source identifiers are absent. Expired windows cannot count against new requests;
  accepted admissions prune up to128 expired rows. T165 still owns scheduled cleanup
  during quiet periods. Fixed windows permit boundary bursts; host/load evidence
  must validate the documented initial policy before production acceptance.
- `deletionStatus(headers, peer): string` requires exact Origin, validates canonical
  32-byte receipt encoding, applies both status limits and returns only its SHA-256
  lookup hash. It has no session dependency and cannot delete/create/sign in/read
  progress or claim completion. T046 must reject account selectors/body/query data,
  consult the external receipt ledger and supply bounded polling/backoff behavior.
- `problem(Throwable)` emits no-store fixed allowlisted code/message/status and a
  fresh server UUID, with Retry-After for429/503. Unexpected exception details collapse
  to one503; no exception/query/body/token data is copied. `logRecord` accepts only
  known operation names, bounded status/duration, a UUID and known fixed reasons.
  It returns exactly route/status/duration/requestId/reason. T165 owns the private
  sink and seven-day retention; no raw-request log sink was introduced here.

Implementation decisions were checked against primary documentation for
[PHP cryptographic randomness](https://www.php.net/manual/en/function.random-bytes.php),
[HMAC](https://www.php.net/manual/en/function.hash-hmac.php),
[timing-safe comparison](https://www.php.net/manual/en/function.hash-equals.php)
and [HTTP cookie syntax and scope](https://httpwg.org/specs/rfc6265.html).
Those references support the primitives; runtime service tests supply the scoped
behavior evidence and do not establish browser/host/provider acceptance.
