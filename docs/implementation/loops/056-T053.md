## Save and identity details

Save tests create two distinct accounts and two independently saved slots before
each hostile write. Complete accounts/identities/preferences/saves/write-receipts/
deletion-proof rows are compared after rejection, so a fixed error response alone
cannot hide a mutation. Tests cover malformed/empty/deep/trailing/BOM JSON,
overlong UTF-8, encoded surrogate codepoints, Unicode beyond U+10FFFF, lone escaped
surrogates, invalid structures, unknown fields/versions/registries, false safe
states, unearned objectives/party membership, account selectors, mixed cookies
and CSRF, exact Origin, duplicate case-variant Origin and conditional/key/mode
syntax. Malformed UTF-8/JSON is400; valid JSON with invalid schema/content is422.

Unicode controls independently admit4096 astral codepoints and4096 combining
codepoints, preserve escaped surrogate-pair representations and exact raw saved
bytes/hash, and reject4097 astral/4098 combining codepoints. Script/SQL-looking
notes remain authorized plain text without executing SQL; this does not claim a
browser XSS rendering check. A genuine native PUT accepts262144 bytes including
padding and rejects262145 bytes while preserving both slots. This distinguishes
raw UTF-8 bytes from note codepoints. New cases do not modify T036 expected data.

Identity cases instantiate actual Auth, AuthTransactions, Sessions, Security,
RecoveryAccountAccess, Google SDK and GitHub GenericProvider/S256 against fresh
isolated stores. Only the trusted provider HTTP constructor handler is synthetic;
there is no production environment flag or HTTP identity bypass. Ephemeral RSA
keys stay in memory and Google uses the installed signature verifier. Tests
reject forged/unknown/symmetric/unsigned signatures; wrong string/array audience;
forged issuer; missing/forged/reused nonce; expired token; future iat/nbf; wrong
authorized party and absent subject. GitHub rejects string/float/zero/negative/
missing stable numeric IDs and unexpected repository scope. Transport exceptions
and upstream503 expose only fixed failure pages.

Forged, expired at600seconds, wrong-session, wrong-provider and revoked-session
state fail before any provider HTTP handler call. Rejected provider evidence
consumes its transaction and replay cannot call the provider again. A nonce from
a canceled attempt cannot authorize a fresh state. Positive synthetic SDK controls
for both providers rotate session/CSRF, then demonstrate replay cannot create
another account or rotate again. No failed identity case creates an account,
preferences, save, receipt or delete-purpose proof.
