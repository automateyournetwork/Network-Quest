## Concrete correction and authority boundary

`introduction-graybox.ts` renders original primitive Three.js geometry for the
actual R01/R02. The JSON layout is strictly validated and frozen: only room IDs,
camera, shape/scale/color placements and safe-point positions are allowed. Tests
join every actual hotspot, exit, floor and safe point exactly once to this map.
Runtime rejects missing/extra projected objects or an unknown safe position.

The application now creates the existing RoomAdapter and bounded ResourcePool
with each panel lifetime and forwards `(view, capture)` directly to shell render.
No status callback rerenders the app recursively. The projection carries the
actual safe-position ID, canonical verb/object controls and notebook evidence.
Meshes, numbered pins and full visual labels only select the current canonical
control. Pointerdown captures once; click dispatches that exact DeferredIntent.
Drag, pointercancel, outside release, blur, hidden pause and teardown cancel it.
The renderer owns no reducer/network/save/reward port. The same native keyboard
controls stay outside the aria-hidden visual-only surface. Explicit scene
recovery controls are also outside that surface.

One WebGL context/canvas is reused across normal projections and room changes.
Each preparation leases two primitive geometries, owns its materials/listeners/
ResizeObserver and cancels its frame on disposal; the pool releases/trims room
resources. New Adventure disposes the whole factory/context and starts a fresh
one. Context loss leaves text play available and requires explicit visual retry.
Rendering is on demand, with no animation loop or external media request.
Reduced motion cannot delay feedback. Visibility events pause presentation;
actual native background-tab behavior remains unverified as explained below.
