## State behavior

Closed `NotebookOperation` variants accept only notes text, a hypothesis UUID/text,
or an inspection UUID. The canonical reducer performs adventure/version/action
receipt checks, requires a safe activity with no pending transition, and commits
the full resulting game once. No renderer-provided effect, measurement, rule
result, configuration version or arbitrary game patch is accepted.

Notes use save v1's 4096 Unicode code-point bound. Hypotheses require non-whitespace
text of at most 512 code points; any wording is accepted, without hidden answer
matching. Unpaired surrogates, malformed shapes, reused measurement UUIDs,
contradictory hypothesis UUID reuse and collection overflow reject atomically.
Identical hypothesis UUID/text replays are a no-op; normal action receipts prevent
duplicate writes. Notes leave physical configuration unchanged and preserve
in-flight save request bytes/captured generation and acknowledgements while
advancing the current dirty generation.

Pinning requires actual recorded endpoint/path facts, the current R02 location
and exact authored choice/conditions. It appends an `open` player hypothesis and
applies `EFFECT-hypothesis-pinned` in the same transaction. Hypotheses are not facts.
Existing save v1 fields remain unchanged; retry retains journal entries while
marking old measurements stale, and Restore Save replaces the whole snapshot.

Inspection requires the actual R01 hotspot/choice, reusable inspection kit,
reviewed copper profile and supported path mode. Typed T023 mapping uses missing
or `service-loop` mode → 95 m + 10 m, and `direct` → 85 m + 10 m. After preparing
the exact repeatable `EFFECT-inspect`, `evaluateCopper` runs against the resulting
candidate world, before any store commit. The new reading uses that evaluator's
actual version. A malformed profile/result rejects the entire candidate including
the provisional flag. Prior readings are never relabeled or overwritten.

## UI and stable integration

`createNotebookController({bus,registry,store})` returns `hotspotBindings`,
`panels`, `project() → {view,capture}`, `invalidate()` and `dispose()`.
Its inspection bindings support bare Use with a held kit or explicitly selected
kit; the hypothesis-board port opens the actual editor. Exact room/hotspot/choice/
verb/tool checks supplement the T025 planner. The internal display JSON import
is validated at composition. `introductionNotebookEffectBindings` supplies the
canonical repeatable inspection and once-only hypothesis marker bindings.

`createNotebookPanel(host,dispatcher)` consumes only detached views and capture
scopes. Five named semantic regions present Objectives, Evidence, Hypotheses,
Maps and Personal Notes. Facts retain actual source text and room labels;
measurements retain numeric readings, current/stale classification and original
configuration/attempt. Endpoint and ordered path lists use explicit authored
display metadata with required recorded fact IDs. Map references only highlight
visited locations; they cannot move the player.

Objective pins and highlighted map location are transient interface state that
travels across rooms. Save v1 has no objective-pin field, so no new durable field
was invented. Hypothesis entries themselves persist as the pinned player writing.
Call controller `invalidate()` together with `bus.invalidate()` when restoring,
starting a new adventure, logging out or returning to title. The transient editor
scope then clears abandoned drafts, while status-only redraws preserve captures
and input focus. Composition retains its original scope and cannot migrate an
old IME commit into a restored adventure. Notes enter the next safe snapshot;
the UI never describes memory as a completed server save.

The DOM uses native buttons/textareas, visible source/freshness text, `textContent`
and textarea values. It has no `innerHTML` path or HTML `maxlength` (which would
incorrectly count UTF-16 units). Over-limit input remains editable with feedback;
it is not silently truncated or passed into the throwing semantic shape guard.
W/L/T/U/I/N/C remain suppressed while editing. IME composition delays note writes.
Section/feedback IDs are whitespace-free and controls have explicit native labels.
