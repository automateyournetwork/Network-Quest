## Service and configuration contract

`Configuration::load(explicitAbsoluteJsonFile, allDocumentRoots)` accepts exactly
its fifteen explicitly typed fields, rejects missing/unknown/duplicate/escaped duplicate
keys, and never evaluates PHP or discovers `.env` or ambient credentials. It
requires a canonical nonsymlink mode0600 file in a mode0700 directory outside all
explicit canonical docroots; open-file inode/device checks prevent adopting a
different opened file. Same-UID/root hostile path races are outside ordinary PHP
path-check guarantees. The dedicated database path is separately checked against
all docroots and is never opened/migrated by loading configuration.

Origin is exact HTTPS without userinfo/path/query/fragment; the canonical game
path derives api/v1. Each configured callback must equal origin + game path + its
provider callback suffix. Rate key is canonical unpadded base64url of32 bytes,
decoded only internally. Credentials must be explicit bounded values. There is
no test-auth, provider-handler, redirect, identity or environment selector.
`config.example.json` is intentionally invalid until privately configured;
`config.example.php` is retained and labeled historical, nonexecutable planning.
Additional required fields are ledgerFile, rollbackRoots (bounded canonical list),
backupSeconds, restorationSeconds and retentionEvidence. The recovery file must
lie outside every declared rollback/docroot, and rollbackRoots must cover the
active game DB. Numeric retention inputs have no production defaults: open must
match the policy already recorded during explicit ledger provisioning. Actual
longest host retention remains an external acceptance input.

`AccountAccess::run(callable): mixed` is mandatory trusted composition. Acquire
the external deletion barrier before any SQLite transaction, reconcile retained
markers before the synchronous callback, hold it through callback transaction
completion/rollback, then release on every exit. The callback must not recurse
into run or perform provider/network IO. There is no permissive production
default. `Support/DirectAccountAccess.php` exists only in tests; AuthRoutesTest's
separate gate exposes rejection/held-state races explicitly.

`AuthTransactions(Database, Sessions, AccountAccess, ?clock)` now protects begin
and consume with that gate. Route admission finishes its own protected operation
before adapter.start invokes begin, avoiding nested barriers. Callback admission,
state consumption and final account commit each acquire their own short barrier;
all provider IO is between those guarded operations. The final operation rechecks
Sessions::within, so logout/deletion during provider exchange cannot authorize
an old context. Shared provider tests received constructor-only fixture changes;
the actual Google/GitHub adapter sources were not changed.

`Auth::handle(method, relativeRoute, rawQuery, rawHeaderPairs, bodyStream, peer)`
implements GET session, POST provider start and GET provider callback. It bounds
and validates raw headers before request processing, reads bounded actual body
bytes, validates socket peer rather than arbitrary forwarding headers, and applies
exact Origin/CSRF and existing auth-start session/source quotas. No new callback
or guest-bootstrap quota is invented: upstream bootstrap abuse control remains a
production admission requirement. Query parameters use a bounded raw decoder,
reject duplicates even after percent decoding, arrays/aliases/control bytes,
malformed escaping and wrong code/error shapes. Bounded known provider UI/error
metadata is discarded; it cannot select identity or a return URL.

Start accepts exactly one JSON purpose member, no return/account selector, and
serializes expiresAt in UTC date-time form. Guest GET issues stable CSRF and a
Secure/HttpOnly/Lax host-only path-scoped cookie through actual Sessions. Existing
GET reuses that CSRF. Account GET projects only provider, bounded display name or
neutral fallback, expiry, current preferences/revision and whitelisted current
slot summary. It reads no save payload and exposes no account ID, subject, hashes,
provider token or deletion proof. Summary revision/time/version/adventure fields
come from authoritative columns, with episode/room/outcome whitelisted from the
summary. An unknown stored save version remains readable as metadata.

Callbacks consume one-use state before network exchange, including cancellation.
After provider verification, final Sessions::within runs inside the short guarded
BEGIN IMMEDIATE. Identity resolution uses provider+subject only. New account,
identity, preferences and rotation commit atomically; existing identities retain
preferences/save. Cancellation changes neither account nor cookie. Wrong-account
delete reauth creates no account and leaves the current session valid. A failed
preferences insert rolls back account/identity creation and rotation while the
already-consumed OAuth attempt stays consumed.

Forward `002_delete_reauth.sql` creates `delete_reauth_proofs` with session_hash,
account_id, confirmed_at and expires_at=confirmed_at+300. The composite foreign
key to unique sessions(id_hash,account_id) binds the proof to the actual account
and cascades on session revocation. No provider identity is duplicated. A correct
same-existing-account delete-purpose callback rotates, then inserts the proof for
the NEW session atomically; rotation cascades old attempts/proofs. Ordinary login
creates no proof. Ages299 and300 seconds pass,301 fails as directed by root;
ordinary auth_time or token iat never substitutes for the purpose-bound roundtrip.
T045 was notified to use that same inclusive five-minute boundary.

Migration001 is unchanged. Database's explicit packaged migrate list is now1+2;
GET/open never migrate. Existing alternate-history rollback tests explicitly
start from001 so failure checks still exercise actual SQL rollback, and their
unknown future version is now3 beyond the packaged latest2. Packaged checks verify
both checksums, proof table, idempotency and independent connection contention.

Callback pages contain fixed accessible main/h1/title/language text, no provider
error or identity echo, no-store/no-referrer/noindex/frame denial, and a CSP hash
for the small script. postMessage contains only type=network-quest-auth-complete
and the exact trusted origin target. It carries no tokens, identity, status proof
or CSRF. The retained tab must validate origin/source and GET session. Browser
execution/accessibility acceptance of that page remains later work.

bytes. The local proxy token and Host/Origin/HMR/path controls remain intact.

responses. No request URLs, raw headers or provider values enter diagnostics.
