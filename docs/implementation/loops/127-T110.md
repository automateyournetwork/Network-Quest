## First-pass findings and corrections

- The first build could not import the sibling workshop recipes. The first
  reopen therefore had no source file to open. Adding the source directory to
  Blender's module path fixed the import. All subsequent runs used factory
  startup and two render threads. The first successful relief model and its
  early reviewed render were retained.
- Initial source and GLB images showed the easel supports piercing two lower
  corners of the plan sheet. The first frozen-camera capture clipped the
  tall furnace flue and the faceted hearth looked like pointed stones.
  Moving the supports behind the vellum, shortening the upper flue, and
  authoring layered emissive tongues above clinker corrected the issues.
  The two revised models were reopened and exported again. All ten were
  compared against the final source and the stage was captured again.
  [Initial comparison](../../evidence/spec001/prop-production/T110/first-review/preparation-comparison.jpg) ·
  [Initial camera](../../evidence/spec001/prop-production/T110/first-review/staging.png)
- The first fragment audit rejected an axis description longer than the
  schema's 32-character limit. The corrected field specifies both up and
  facing axes within the existing limit. The repository asset schema and
  inventory audit then passed on the twenty rows with zero issues.

## Reproduction

From the repository root, run Blender with `--factory-startup -b -t 2
--python-exit-code 1 --python assets-src/props/R01-R02/model.py --` followed
by the desired PR011–020 IDs. For each resulting native file, start a new
Blender process with that file and the same flags, calling the adjacent
`reopen.py`. A separate factory-empty Blender process runs `compare.py`.
Pinned Node runs `browser.mjs`. The existing project Pillow interpreter
runs `sheet.py`; Python 3 runs `records.py` for the production records of
this specific reviewed run. Rerunning the build produces a new source
revision requiring fresh verification and review evidence. Check the
fragment with pinned Node and `tools/validate-assets.ts --manifest
assets-src/props/R01-R02/manifest.json`. Coordinator-owned global tracking,
consolidation, quota acceptance and publication are separate operations.
