## Concrete implementation

- `createReducer({ registry, bindings, canReachRoom? })` creates a pure command
  reducer. `ReducerCommand` carries action ID, adventure ID, expected configuration
  revision and attempt ID. `ReducerInput` supports immediate application,
  begin/commit/cancel, explicit item recovery, an encounter rewind primitive, and
  exact no-op canceled logout. Domain evaluators still own technical correctness;
  this module has no networking physics, DOM, audio, auth, network, storage or
  runtime AI operation.
- `createReducerState(runtime)` wraps the existing runtime in transient control
  state. Action receipts, pending request snapshots, revision high-water mark and
  used attempt IDs remain outside `GameState`. Rejected actions preserve the exact
  input state. Accepted no-ops remember their action IDs without changing runtime
  or dirty state; canceled logout preserves even the wrapper's identity.
- `EffectBinding` resolves each selected effect against its exact authored
  definition and ancestor conditions through T015's registry. Payload changes,
  unknown IDs, duplicate supplied effects and ambiguous bindings fail closed.
  Stable IDs shared under different completion anchors are rejected explicitly;
  there is no second reward route under another action ID.
- One-time receipts use existing completed objective/quest IDs, actual dialogue
  effect IDs, or declared true-valued flag effects. A dialogue receipt must be an
  actual effect included in its atomic group. A flag receipt must include its
  authored marker, and a bound effect cannot clear that marker. No generic ledger
  is inserted into dialogue fields and no invented persisted ID is allocated.
  Long content IDs that exceed save-v1's narrower ID syntax/length are rejected.
- Objective/quest completion uses an explicit atomic batch from the authored
  alternative: that alternative's effects plus common effects. Either valid
  alternative can independently complete the shared receipt; mixed and partial
  alternatives are rejected. Other shared receipt groups are indivisible.
  Grants/consumption/completion cannot be configured as repeatable effects.
  Repeated legitimate configuration adjustments remain possible through distinct
  action IDs and repeatable authored effects.
- All debits must be affordable before any reward is credited, regardless of
  supplied effect order. Consumption, reward, completion, receipt and destination
  commit together. Inventory, party/subset, relevant collection and numeric bounds
  are checked before committing. Begin stores a copied request without changing
  game or dirty generation; commit rechecks the current versions and preconditions.
  Cancel restores the prior committed activity/world. Old callbacks cannot apply
  after cancellation, another attempt, or fresh state installation.
- Physical/configuration changes conservatively invalidate every measurement and
  advance the configuration generation. Learning-only facts do not invalidate an
  otherwise current reading. `isMeasurementCurrent` requires both generations and
  explicit freshness to agree. Generation exhaustion rejects atomically instead
  of wrapping. Activity-only changes need no fictional world/dirty change.
- Never-consumed tools cannot be consumed. Documented transformations are resolved
  across their declaring items: a single combination on A can consume A+B without
  a reciprocal declaration on B. Each consumed item's own recovery and the
  combination's recovery must be available in the final candidate world. Later
  actions cannot strand an absent consumed essential tool by closing its recovery.
- `recover-item` is an explicit action at the available authored source. It needs
  a durable receipt proving a documented consumption and restores one missing
  tool, never tops up an existing quantity. It does not clear the old consumption
  or reward receipt. A different later documented consumption can be recovered
  again, while replay cannot produce extra items or outputs. There is no blanket
  inventory refill.
- `rewind-preparation` is a foundation primitive for T084, restricted to failure
  or shutdown and an adventure-matching checkpoint at a registered safe preparation
  position. It copies reversible world/inventory/recruit/reward state, retains
  the current learning journal, makes old readings stale, requires an unused
  caller-supplied attempt UUID, and advances revision above current/checkpoint/
  retained-reading history. It never saves, loads a server slot, creates a second
  durable checkpoint, or changes identity. Checkpoint capture, encounter rules and
  confirmation flows remain later integration.

## Tests before implementation and review corrections

The initial test file was written and run before the reducer existed: the observed
red result was the missing `src/state/reducer` import. Subsequent edge cases were
added and observed failing before the corresponding correction. Assertions are
independent state examples, not expected physics answers generated by evaluators.

Early tests used deliberately small typed registry stubs. Coordinator review
identified two integration gaps: treating all alternatives as one mandatory group,
and requiring reciprocal transformation declarations. Added two complete authored
fixtures that pass the actual `validateContent` boundary before exercising the
reducer. The fixtures retain real reviewed source claims and metadata and are
decoded as independent JSON objects, just like on-disk documents. Both defects
were reproduced and corrected. These fixtures are in-memory tests, not production
content or additional completed rooms.

Additional red/green regressions cover recovery after a second legitimate
consumption, changing recovery conditions, unsupported optional predicates,
no-op action reuse, wrong adventure, active-party subset, generation exhaustion,
receipt marker ownership, inventory overflow, save-v1 wire IDs, pending request
mutation, late callbacks and safe-activity-only transitions. The flag receipt
snapshot is validated against the unchanged actual `save.schema.json` with Ajv
Draft 2020-12 plus formats and strict mode. `allowUnionTypes: true` supports the
schema's explicitly declared flag value union; no schema keyword was disabled.

## Remaining integration boundaries

- T017/T026/T028 and later adapters must construct identified commands from
  semantic actions and bind the actual authored effects. The reducer validates
  registered safe destinations; navigation still owns unlocked-path/exit policy.
  Remote transformation recovery needs a pure navigation reachability adapter.
  The default proves only recovery in the current room and conservatively rejects
  other recovery locations. Explicit recovery occurs at its actual source.
- The reducer consumes explicit authored effect definitions. It does not synthesize
  arbitrary consumption IDs, acquisition grants, progression, hints, measurements
  or minigame completion state. Minigame-complete predicates are currently
  unsupported and fail closed, including under negation; T100 must provide the
  reviewed authored completion mapping rather than inventing a save field.
- T084 owns checkpoint capture and full encounter retry/E03 classification/UI;
  later save/auth tasks own validated snapshot installation, persistence receipts,
  Restore Save warnings, logout confirmation and actual single-slot transactions.
  An installed snapshot replaces its whole world/journal; it is not the retry
  primitive. This module preserves autosave choice and never queues a write.
- Input runtime state must come from a trusted constructor or the future validated/
  migrated snapshot boundary. Local invariant checks do not replace complete save
  schema/registry/semantic validation. Production content and binding definitions
  must come from an accepted immutable T015 registry.
- The app shell does not import the reducer yet. Its passing Vite build establishes
  compile compatibility, not rendered gameplay, browser acceptance, actual saving,
  human learning or an aggregate gate. G0 external evidence and G1–G7 remain open.
