## Concrete change

- [Domain types](../../../src/domain/types.ts): nominal episode-qualified content
  IDs, separate runtime identities, configuration/attempt versions, all ten save-v1
  units, and a unit/value-correlated reading union. The pure synchronous evaluator
  interface takes a challenge, identified action and relevant world, returning the
  four contractual statuses with reason, observations and identified effects.
  `invalid-input` and `content-error` require an empty effects tuple; an explained
  incorrect action may still have consequences.
- [State types](../../../src/state/types.ts): immutable world, notebook,
  measurements, hints and outcome history, with every save-v1 property retained.
  `GameState` is the durable candidate; `SaveSnapshotV1` adds only the exact schema
  version and safe-boundary envelope. `RuntimeState` separately contains gameplay,
  activity, UI, checkpoint, persistence and auth state. Account identity, provider
  tokens, server revision and timestamps are absent from the writable game/save.
- Checkpoints capture only reversible world/preparation. Learning history lives
  outside the checkpoint, including hint use and previous outcomes. Freshness
  carries attempt, configuration revision and explicit stale state. Comments
  preserve Retry/E03 Continue rollback, fresh generation, retained learning,
  Restore Save replacement, and canceled/confirmed logout semantics.
- Transient persistence distinguishes dirty/acknowledged generations, unknown vs
  empty server slot, exact pending bytes/key/precondition, replacement consent,
  auth generation and the five save UI states. Server acknowledgement metadata is
  separate, including a replay older than the current slot. This declares the
  boundary; it does not implement its transactions or defaults.

## Limits and handoff

Types are not runtime validators or proof that every constructed object is safe to
serialize. TypeScript structural assignment and explicit casts can bypass excess
property checks. JSON schema and future registry/semantic validation remain required
for exact fields, ID syntax/membership, finite numbers, numeric/collection/text
bounds, UTF-8, party subset/uniqueness, safe positions, freshness and write policy.
The type brands deliberately provide no unchecked factory. Actual constructors,
validators, reducers, transitions and tests belong to their planned later tasks.

No current physical rule is implemented or scored. The source register's original
R/O/CH/PR/SQ/MG/rule IDs are neither changed nor replaced with a new enumeration.
T013 owns the authored registry and content schemas; T014 owns independent fixture
transcription before evaluator implementation. T015 and later runtime work must
enforce the declared boundaries. Real logout/retry, save/replay/conflict, provider,
browser and episode acceptance remain untested. G0 remains blocked; G1–G7 remain
pending. The coordinator owns task checkboxes, state, handoff and gate updates.
