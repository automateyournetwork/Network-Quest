Implemented `src/ui/verbs.ts` and `src/ui/inventory.ts`, with a small transient

input uses the existing captured action bus. The bus gains only typed inventory
and explicit hotspot-choice intents, with exact runtime shape guards. Its epoch,
captureScope, cancel, replay and synchronous commit behavior is unchanged.

Verbs resolve only current-room hotspot IDs, explicit offered entry choices, or
local floor/exit IDs. Globally registered action IDs are not scene targets. An
explicit binding names room, hotspot, verb, action, source dialogue and optional
held item. It must identify that source's exact entry-node choice and the
hotspot's exposed action. Entry and choice conditions are checked against the
current world; multiple eligible actions remain meaningful authored choices,
never a first-array-entry guess. Unsupported verbs use the hotspot's authored
feedback. Look without an action binding describes the object; bound Look applies
the actual authored record-fact batch and displays its evidence. Looking at a
character alone does not grant its dialogue clue.

Inventory selection/deselection is transient UiState only. Rows retain authored
names/descriptions and explicit quantities. Both inputs must be held, uniquely
identified, valid quantities and support Use. Recipes come from either input's
actual authored combinations and require conditions; multiple recipes need an
explicit recipe choice. The existing reducer owns all debit/reward, effect
identity, one-time receipt, nonconsumable-tool and recovery decisions. Same-item
inputs accumulate debits before credits. A consumed cursor selection clears in
the same compare-and-set as the reducer candidate, without another gameplay or
persistence mutation. Recovery uses the existing recover-item reducer operation.

No invented ledger or production recipe was added. The introduction has one
nonconsumable kit and no recipes. Recipe tests use clearly identified fixture
records passed through the real content validator and actual reducer; production
Look, kit and selector tests use the real introduction. Canonical kit issuance
uses `EFFECT-kit` + `EFFECT-kit-issued`, `FLAG-kit-issued`, and
`DIALOGUE-photon-intro`; repeats grant one kit and do not add dialogue receipts.

The condition implementation moved from reducer-private functions into
`src/state/conditions.ts`. Public `conditionSatisfied` checks the whole expression
for support before evaluation, including `not`/`any`. Existing reducer semantics
and atomic batches/receipts are preserved; all 38 existing reducer cases pass.

## Stable integration handoff

- `createVerbController({bus, registry, store, bindings, walk?, panels?})` owns
  select-verb, interact, choose-hotspot-action, open-panel and close-panel. It
  returns `controls()`, `objects()` and `dispose()`. The seven visible controls
  reuse the existing shell's W/L/T/U/I/N/C shortcuts and input-edit suppression.
- `HotspotBinding` uses `mode: 'effects'` for explicitly approved static authored
  choice batches, or `mode: 'port'` plus a trusted `InteractionPlanner`. The
  planner receives `{room, hotspot, choice, verb, itemId}`, the original captured
  action and reducer state, and returns a synchronous `ActionPlan`. Resolution
  must be pure and commitment synchronous; store identity is rechecked.
- T026's Talk bindings name narrator `DIALOGUE-arrival-actions` /
  `DIALOGUE-workshop-actions` as choice sources, and explicitly map the target
  Photon/Titan dialogue in their planner. Source IDs are not guessed target
  dialogue IDs. T026 received this interface before starting disjoint work.
- T027 measurement and hypothesis handlers must use ports that validate and
  commit actual measurements/player input. The controller does not turn static
  `FLAG-path-inspected` / hypothesis flags into evidence. T028 supplies safe
  navigation and graph checks. T029 constructs/wires the real guest application,
  notebook/compendium availability and O01/O02 semantic completion checks.
- `GameplayStore` in `controller-store.ts` is the existing
  getState/reduce/compareAndSet adapter. `uiPlan`, `guardedPlan`, and
  `reductionPlan` are shared synchronous helpers; they never accept arbitrary
  game patches from renderer intents.
- `createInventoryController({bus, registry, store})` owns select-item,
  combine-items and recover-item. `inventoryView(registry, state, itemIds?)`
  supplies readable rows and explicit recipe controls. An explicit item catalog
  can expose recovery-source controls; actual receipt/eligibility is still
  checked by the reducer. `createInventoryPanel(host, dispatcher)` renders keyed
  native controls, preserves focus, restores focus on close and retains supplied
  projection capture scopes through presentation-only updates. Removed buttons
  cannot activate through detached direct event listeners.
- Main/bootstrap, auth/save, notebook, navigation, dialogue, objectives and media
  were not implemented by this task. Missing ports return honest unavailable
  results. The nine T022 guest browser journeys remain visibly pending for T030.
