## Repository adapter and command

`tools/asset-files.ts` reads only approved public roots. The CLI never executes
content, reaches the network, extracts archives, reads production secrets,
rewrites media, or infers a completed source retrieval from a URL.

The reader denies absolute/traversal/hidden/private/operator/credential/player/
backup/database/test-synthetic/feasibility paths, symlinks (including internal
aliases), nonregular files and over-limit reads. It validates components before
opening, uses O_NOFOLLOW/O_NONBLOCK, checks descriptor identity, admits byte
sizes before allocating, bounds the read and rejects size/mtime changes.
Limits:4MiB per JSON document,256MiB per source/export,1GiB total admitted bytes,
100,000 cached files,50,000 evidence directory entries and8 evidence-directory
levels. The pure port separately bounds data depth/nodes, evidence entries,
2million graph steps and10,000 issues. Exceeding these limits fails explicitly;
it does not accept partial release counts. Production libraries beyond these
limits will require an explicitly reviewed streaming/partitioned adapter update
before acceptance; current testing makes no large-library performance claim.

Independent records are discovered as one `AssetEvidenceRecord` per JSON file
under `docs/evidence/spec001/assets/`, plus explicit source-reopen/verification/
usage evidence paths. Production/retrieval records use that discovery subtree
because the manifest schema has no production evidencePath field. Records are
parsed directly from their bytes; there is no trusted normalized sidecar.
Retrieval needs actual archive and materialized member bytes, matching observed
hashes, version/member/instructions, public availability and no authentication.
No network retrieval is attempted by this validator; T145 remains separate.

The adapter loads the real registered `world.documents` through the existing
content validator. Roster/assetId/manifest.usedBy assertions alone never create
runtime uses. Only exact authored assetId/contentId/use/exportPath/interaction
bindings can normalize into observations, supplemented by separately recorded
placement/browser evidence. Current content/presentation is graybox and has no
final export bindings. **T066 and later integration must add the genuine shared
presentation/media resolver and schema bindings before production assets can
count.** The adapter deliberately reports no such use now.
