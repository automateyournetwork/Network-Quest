## Result and public interface

Scoped implementation is complete and frozen for root review. This is local
controller/API-port verification, not actual browser/provider or aggregate G2
acceptance. Requirements: C6/C12, FR-010/012/013/014, NQ-11, SAVE04–09/13.

`new AutosaveController({api, coordinator, store, debounceMs?})` uses the actual
GameApi and SaveCoordinator plus the existing synchronous state/CAS port.
Default trailing debounce is750ms; explicit values must be integer1–5000ms.
The bound is an engineering default, not a new gameplay timing requirement.

- `observe()` runs after each committed gameplay transition and after controller
  subscribers finish. It owns its prior state instead of trusting caller-supplied
  old snapshots or an arbitrary “safe” event. A real dirty-generation increase
  and game change can nominate a changed room. A real entry into safe preparation
  may also nominate earlier unsaved changes without another game mutation.
  UI renders, no-op actions and notes alone never nominate an autosave.
- `objectiveFeedbackDismissed()` is a separate actual user-dismissal hook.
  Newly completed objectives are tracked; rendering feedback or observing a null
  UI feedback value does not prove dismissal. A bare/duplicate dismissal does
  nothing. T050 added the actual dismissal control in its separately owned work.
- The debounce stores context/attempt/timer identity, not snapshot bytes.
  Delivery rechecks current safety, lifecycle, account opt-in, dirty/acknowledged
  generations, known same-adventure slot and coordinator status, then invokes
  `coordinator.save('automatic')`. That call captures current bytes through the
  accepted validator, so later personal notes join the snapshot and the reducer's
  single dirty increment is not duplicated.
- Pending reducer transitions, dialogue, pending effects, room transitions,
  cutscenes, encounters, terminal failure, shutdown and current E03 block writes
  and cancel queued work. E01/E02 require safe-continue; the coordinator's current
  content policy still verifies the authored Continue anchor. Returning to stable
  activity alone never resurrects a canceled timer.
- Failure/E03 rewinds are not triggers: prior/current terminal states, changed
  attempts and newly appended E03 history cancel the transition. An independent
  later eligible action may persist the retained learning under the same rules.
  No checkpoint fallback or shutdown snapshot is used.
- First/other-adventure adoption remains manual; an unread, unsupported, conflicted
  or pending slot cannot be auto-adopted/replaced. Manual I/O cancels queued work.
  Keep Playing is enforced by the actual coordinator. Unknown outcomes keep the
  coordinator's frozen operation; no automatic retry, fresh replacement write or
  acknowledgment-based follow-up is installed.
- `invalidateView()` must precede New Adventure, Restore, account/logout runtime
  replacement, including same IDs/counters. `dispose()` is terminal. Each resets
  owned callback/review identity and cancels timers without claiming an already
  sent save was undone. Service notifications and preference results also guard
  reentrant lifecycle/choice changes.

Preference ports are separate from progress snapshots:

- `capturePreferencesReview()` returns an opaque owned review containing the
  last confirmed ETag/value and `AUTOSAVE_EXPLANATION`: the same single account
  slot, account scope across devices, initial off state and manual first adoption.
  Copies and old lifecycle contexts are not permission to mutate preferences.
- `setEnabled(review, enabled)` is an explicit user choice. It uses only
  `PATCH /preferences` with the reviewed ETag and the autosave boolean. Opt-out
  cancels queued work and projects local off immediately, including when a
  current owned review has a stale ETag (that stale review sends no PATCH).
  Network failure is shown as unconfirmed; server-wide off is not claimed.
- A successful PATCH does not mutate GameApi's session cache. The controller
  explicitly GETs session and validates the same coordinator/API/runtime context,
  expected or newer preference revision and selected value before projecting
  enabled. It does not call bindSession or erase known-slot/acknowledgment/pending
  save metadata. Older enable results, late GETs and reentrant success callbacks
  cannot supersede a later opt-out or replacement account/runtime.
- `refreshPreferences()` is an explicit read-only recovery operation. It never
  retries PATCH or enables an opt-out/new-run local pause merely because the
  server says true. A new deliberate reviewed choice resolves differing settings.
- `state`/`subscribe` expose current preference status, local enabled projection,
  last-confirmed cached server choice, queued state and honest explanatory text.
  An in-flight prior save may still finish after opt-out. No browser storage,
  persistent draft, second slot, arbitrary account identifier or implicit sign-in
  was added.
