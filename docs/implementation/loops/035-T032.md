## Stable T033/T034 interface

```ts
evaluatePacketJourney(
  challenge: PacketJourneyChallenge,
  action: DomainAction<PacketJourneyInput>,
  world: PacketJourneyWorld,
): PacketResult<JourneyObservation>
```

`challenge` contains the reviewed `packetProfile` and `symbolProfile` projections,
explicit complete `bench` premises, and `impairment: null | ToySubstitution`.
The profiles project existing source `id` and `parameters`; they do not import
source fixtures into production. Missing/altered model parameters fail closed.

The action input is `{kind: 'inspect', phase}` with phase
`payload | encode | transmit | decode | compare`, using the existing action ID
and captured `expectedVersion`. `world` extends `WorldVersion` with:

```ts
physicalEvidence: {
  result: ReturnType<typeof evaluateCopper>;
  evaluatedVersion: WorldVersion;
  stale: boolean;
} | null
```

The caller supplies the **actual** evaluator return and its original captured
version. Every invocation checks current revision/attempt against the action,
evidence wrapper, and actual observation version, plus explicit staleness. A
wrapper cannot relabel an old observation. Later phase and replay calls must
invoke this function again with current world state. T033 owns pause/inspection
position and real controls; T034 binds the actual guest world/evaluator. No timer,
renderer completion, cached comparison, or independent success flag is accepted.

The result retains the shared status/reason/observations/acceptedEffects shape.
`observations[0]` is a `packet-journey` or `packet-error`; errors have null recovered
bits/comparison and false transmission success. Outputs are deeply frozen detached
data. Neither input content nor the physical result is frozen or modified.

The trace exposes payload at every checkpoint, encoded symbols from `encode`,
received symbols from `transmit`, recovered bits from `decode`, and comparison
from `compare`. `transmissionSucceeded` can only be true at `compare` with a valid
current physical result and matching highlighted bits. All phases return zero
progress/penalty and empty effects. These are inspection results, not objective
completion or persistence instructions. Phase selection itself does not manage
pause/order; that belongs to the T033 controller.

Other exports are `encodeToyBits`, `decodeToySamples`, `encodePacketPayload`,
`evaluateSymbolAnswer`, and `comparePacketPattern`, with typed profiles, samples,
claims, traces and comparison observations. The two scored answer functions use
existing `DomainAction`/`WorldVersion` guards. A wrong but bounded binary answer
is `incorrect`; absent/malformed learner input is `invalid-input`. Malformed author
profiles/samples/units/positions/data are `content-error` before learner grading.
The physical evaluator's content-error also precedes a malformed journey command.

## Preserved teaching and physical boundaries

The exact reviewed mapping remains −3→00, −1→01, +1→10, +3→11. Literal independent
expectations verify NQ `4E 51` → `0100111001010001` →
`−1,−3,+3,+1,−1,−1,−3,−1` and inverse `4E 51`; T12 → `00101101`.
One symbol represents two bits without byte padding. Positions are explicit
zero-based ordinals in supplied order, not time or wire serialization. Sparse,
unknown, repeated, reordered, missing-unit and malformed input fails closed.
The engineering input bound is 256 symbols / 512 bits, not a physical limit.

These are highlighted bytes inside an opaque upper-interface frame. Returned
scope explicitly denies a whole two-byte frame, universal PHY error detection,
Ethernet FCS validation, whole-route proof and higher-layer service proof. No
seven-header model, analog-voltage/PAM4 claim, bitrate or throughput is created.
`toy-level` remains a local display type, outside save-v1 Reading units.

The supported physical handoff is the existing reviewed copper **length-only**
predicate; its observation, metre units, original version and limited scope are
preserved. Complete bench premises separately declare compatible endpoints/media/
terminations, continuity, endpoint power, other physical conditions and scoped
known-good upper dependencies. PROFILE-PACKET by itself does not supply these.
Missing premises cause content-error and no award even when length is correct.
The valid source length result stays unchanged in the caller's world.

Fixture integration calls actual `evaluateCopper` with its source profile and
fixture operands/action/captured version. `85+10=95` supplies the fresh passing
result; `95+10=105` supplies failure. Repair evaluates NEW passing facts at revision
8 after failed revision 7. Replaying or relabeling the earlier result cannot repair.

A failed copper path does not predict recovered bits. Only the separately supplied
reviewed `last-toy-symbol-substitution` can substitute position 7, −1→−3, on a current
incorrect result. It yields `0100111001010000`, one differing bit at position 15,
and `4E 50`. Failure with no trace yields no received symbols/bits/match at every
phase. A supplied substitution is not applied to a passing physical result.
Unsupported impairment models and correct continuity-only results cannot silently
stand in for this reviewed length-bench composition. Later branch models/R12
