## API and integration obligations

`AuthTransactions(Database, Sessions, ?clock)` uses trusted server time by default.
`begin(SessionContext, provider, purpose='login')` returns private transient
`state`, `nonce` (Google only), `codeChallenge` and integer `expiresAt`. It creates
independent 256-bit state/nonce/verifier values. Only state/nonce SHA-256 hashes and
the server-private PKCE verifier enter the existing `auth_transactions` table.
The S256 challenge uses SHA-256 and unpadded base64url. No raw verifier is returned
in start material or the browser authorization URL.

Begin rechecks the live session through `Sessions::within` inside a short owning
Database transaction. Delete purpose requires an authenticated account whose
stored provider matches the requested provider; its expected account comes from
that session, never request input. A maximum of five outstanding unconsumed
transactions per session across providers rejects extra starts without evicting
live windows. Expiry is exactly600 seconds. Up to128 expired rows are pruned on
start; T165 scheduled cleanup and route-level `Security::limit('auth-start',...)`
remain mandatory. The outstanding-count bound does not replace the request quota.

`consume(SessionContext, provider, state)` rechecks the live session/account and
matches state hash, initiating session, provider, purpose/account binding, unused
status and expiry atomically. It commits `consumed_at` **before** external IO,
including cancellation. Bad state/session/provider/expiry/replay fails400 without
exchange. A provider failure leaves the transaction consumed; the player starts
a new attempt. Logout/rotation's existing foreign-key cascade invalidates pending
attempts. Its returned verifier/nonce hash/purpose/account/times are private
verification material, not public identity or deletion authorization.

`Google(AuthTransactions, clientId, clientSecret, fixedHttpsCallback, ?clock,
?trustedHttpHandler)` takes explicit private operator configuration. It never
discovers environment/service-account credentials. Callback syntax is canonical
HTTPS, with no userinfo/query/fragment/dot segments and the Google callback suffix.
The same supplied callback is used for both authorization and code exchange.
Registration equality remains an actual configuration/provider acceptance check.

`start(SessionContext, purpose='login')` returns only `authorizationUrl` and integer
`expiresAt`. T041 must serialize the timestamp in the API's date-time format. The
URL uses Google's fixed authorization endpoint, response_type=code, S256, the
state and nonce, scopes exactly `openid profile`, access_type=online and
include_granted_scopes=false. No email, offline access, incremental scope union,
userinfo/API calls or arbitrary return-URL input exists. For delete purpose it
adds `prompt=select_account` to request an explicit provider account choice.

`complete(SessionContext, state, ?code, ?error=null)` requires exactly code or
provider error, bounds the callback values, consumes the state, then exchanges
the code through the actual `Google\Client::fetchAccessTokenWithAuthCode` with
the stored verifier. Validated `access_denied` returns null with no identity change.
Invalid grant/claims/signature fail400; transport/upstream failures fail503. It
returns only an **internal** array: `provider`, `subject`, nullable `displayName`,
`purpose`, `expectedAccountId`, and `confirmedAt`. It returns no access/ID/refresh
token, email, picture, complete claims, nonce or verifier. Optional display text
is valid UTF-8, at most128 Unicode characters and control-free; invalid/missing
names become null, and T041 supplies a neutral public fallback without exposing
subject. Valid text is still untrusted: render it as text, never HTML.

T041 must validate duplicate/raw query/body/header structure, exact Origin and
CSRF for start, callback request bounds, source/session rate limits, public
no-store error/completion pages and safe completion hints. Never serialize the
internal context/identity/proof as the callback response. Redact query strings
before any SAPI/proxy/access/application logging; an application adapter cannot
undo a web server's earlier access log. Main-tab identity comes from GET session.

**After provider IO, inside the final account transaction, T041 must recheck the
original context with `Sessions::within`.** Resolve `(provider, subject)` without
email merging, honor deletion-ledger barriers, create/resolve the account and
preferences as appropriate, and rotate atomically. A valid old callback can still
produce transient identity evidence after a concurrent logout; the tested final
session recheck prevents committing it. This adapter is not a route or standalone
authorization proof. Provider IO never holds a SQLite write transaction.

## Cryptographic and transport checks

Installed lock/source versions inspected: google/apiclient2.20.1,
google/auth1.55.3, firebase/php-jwt7.2.2, guzzlehttp/guzzle8.6.0. The Google
verifier checks audience only when that claim exists and has no application nonce
check. The adapter therefore uses the real SDK verifier **and** requires typed
iss/aud/sub/exp/iat/nonce. Accepted issuer is one of Google's two documented forms;
aud must be this one string client ID, never an audience array; sub is bounded,
case-sensitive printable ASCII. exp/iat are integers with zero-skew strict expiry
and issuance checks, regardless of a library-global leeway value. Nonce must have
the generated canonical encoding and match its stored SHA-256 with hash_equals.
Optional azp must name this same client; optional nbf must be a valid elapsed time.
RS256 and a bounded kid are required; unsigned/HMAC/remote-key headers cannot select
another algorithm or key source. Token size is capped at16384 bytes. The transaction
must still be unexpired after exchange/verification.

`ProviderHttp::client('google'|'github', ?trustedHandler)` returns a Guzzle client
whose low-level handler forces fixed exact method/endpoint pairs. The optional
handler is a PHP test seam only: no route/env/config switch or external URL selects
it. Every test intercepts all calls. Production omits it for the installed cURL
handler with certificate/hostname verification, HTTPS protocol only,3-second
connect and10-second total timeout, no redirects/cookies/proxy/debug/history/retry
middleware, and no persistent idle handles. All caller/library request options
are replaced after the PSR request is built, so they cannot disable these limits.

Response bodies use a bounded sink that refuses a write exceeding65536 bytes and
also undergo an actual-byte postcheck. Response headers are checked at the header
callback and on returned synthetic responses:64 names/16384 bytes, canonical
bounded Content-Length, no content encoding, and no redirects. Upstream libcurl
and the hosting transport retain their own lower-level framing/header limits;
this test suite does not certify wire timing/TLS behavior. Only HTTP200 succeeds;
POST400 must carry a JSON error object. Other statuses fail503. JSON is an object
with maximum parsing depth32. Content-Length must match actual bytes.

Google JWK documents additionally require1–16 RSA/RS256 signature keys with unique
bounded kids and bounded canonical base64url modulus/exponent. This prevents the
pinned library's malformed-key-array warning; it does **not** replace key parsing
or RSA signature verification. Keys come only from the fixed Google certificate
endpoint, never a token URL. Invalid upstream key documents are unavailable503;
a well-formed keyset that cannot verify the token fails400.

Errors are fixed `RequestRejected` messages with no chained HTTP exceptions;
SDK logging uses NullLogger. Public problem/log projection remains Security's
allowlisted metadata. Do not log raw exceptions/traces/objects or request/response
bodies. No provider token is persisted. The per-operation SDK/token/claim objects
are released on success/error; PHP cannot guarantee zeroization of every copied
string, so this is lifetime minimization, not a physical-memory erasure claim.

## Fresh deletion confirmation means exactly this

Root clarified the existing contract during this loop: delete-reauth means an
explicit new purpose-bound provider identity confirmation, with same-existing-
account matching and completion no older than five minutes. It does not add an
unwritten requirement to prove a freshly typed password. New state/nonce/code/S256
and account selection establish the new confirmation roundtrip. Token iat and
ordinary SessionContext.authTime are not evidence of newly entered credentials
and never substitute for the explicit delete purpose.

T041 must compare the returned provider/subject to the expected **existing**
identity and reject a different selected account without creating it or logging
the current account out. It must preserve/create purpose-bound same-account
completion evidence for the new session atomically if rotating: rotation deletes
all old-session auth transactions. T045/T046 must consume/check that evidence,
its current session/account and <=300-second completion age, alongside explicit
confirmation/Origin/CSRF and the deletion receipt. The adapter's identity result
alone permits no deletion. These integration checks remain pending.

Primary sources inspected on2026-11-26:

- [Google OIDC](https://developers.google.com/identity/openid-connect/openid-connect)
  documents the code exchange, issuer/subject/expiry claims, scopes, nonce and
  select_account semantics. Its optional auth_time row says: “Provided when the
  auth_time claim is included in the authentication request and enabled in settings.”
- [Google discovery](https://accounts.google.com/.well-known/openid-configuration)
  currently advertises the exact authorization/token/JWK endpoints, RS256 and
  S256. Endpoints are pinned to this reviewed provider contract, not dynamically
  selected from caller metadata.
- [Google Security bundle](https://developers.google.com/identity/siwg/security-bundle)
  explicitly says: “Google does not support Google Account reauth requests.” It
  distinguishes last provider authentication from JWT issuance. Optional session
  age claims require In production/Verified app status, Settings → Advanced
  Settings → Session age claims, and a claims request for auth_time. None of those
  settings or stronger capabilities was configured, tested or required here.
- [OIDC Core ID-token validation](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation)
  supplies the signature, audience, time and nonce validation context.
- Installed `google/apiclient/src/{Client.php,AccessToken/Verify.php}` and
  `firebase/php-jwt/src/{JWT.php,CachedKeySet.php}` were inspected directly rather
  than assuming a decoded payload satisfied application checks.

No credential-entry/max_age/auth_time guarantee or real provider consent-screen
behavior is claimed. If stronger authentication freshness is later desired, it
requires a separately specified and tested protocol rather than relabeling this
completion time. No additional owner setting change is needed for this task.
