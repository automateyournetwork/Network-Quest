## Actual process protocol and isolation

Each child is a new `proc_open` execution of pinned PHP_BINARY, loading the real
runtime classes and only this test's helper. Each opens independent game and
external-ledger SQLite connections against freshly allocated TestEnvironment
storage. Two distinct real Sessions rotations provide separate session/CSRF
credentials; prepared identity and deletion-proof rows are explicit synthetic
inputs, never HTTP authentication flags. Environment inheritance is restricted
to LANG/LC_ALL. No process selects an ambient database or credential path.

The parent and children communicate newline-delimited JSON events and exact GO
commands over private pipes. READY reports distinct child PIDs. Conditional
writers independently GET/review the empty slot or revision8, then both enter the
actual PUT handler and stop at the repository's fixed `validated` phase after
initial receipt misses. The parent verifies both are alive at that barrier before
releasing either winner. These are overlapping operations with controlled commit
order, not sequential calls renamed concurrency. Both winner orders are tested
for empty-slot creation and revision8 replacement. No sleep determines a winner.

Initial receipt checks pause at `admitted`; final receipt/authorization checks
pause at `validated`. Those observer events assert no SQLite transaction is held.
For save-first account races, a **connection-local TEMP trigger** invokes a
SQLite function after the real slot update and before receipt insertion. That
function reports `inside-write` only with a real active transaction. Production
`trusted_schema=OFF` stays enabled; no persistent trigger or pragma weakening is
needed. An independent connection sees only committed revision8/eight receipts.
The already-started competing account worker demonstrates a failed nonblocking
flock on the actual external barrier, then enters its actual route. Releasing the
save lets its transaction commit before logout/deletion can linearize.

Response loss is at the worker output boundary after the real handler returns.
The test control checks an independently supplied expected committed revision and
status200 before discarding the response; only a completion marker is emitted.
The retry receives no previous acknowledgement. This prevents a hidden save503
followed by successful deletion from falsely satisfying a save-first test.
This is deterministic lost-response injection, not a claim of network packet loss.

Pipe reads and child input have eight-second timeouts. Normal workers must emit
no stderr, exhaust stdout without timeout and exit0. Failed tests close pipes,
terminate their children, escalate after200ms if necessary, and reap processes.
The explicit precommit SIGKILL test verifies SQLite rollback and external-lock
release. TestEnvironment checks owned inodes and removes both temporary0700
namespaces; every test asserts both directories absent after cleanup. No broad
RuntimeException catch can swallow PHPUnit assertions: this file has no such
catch.
