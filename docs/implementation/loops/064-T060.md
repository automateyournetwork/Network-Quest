## T061 interface proposal, reviewed with root

The fixture-owned TypeScript exports document the pure synchronous interface:

```ts
validateAssetManifest(manifest: unknown, evidence: AssetEvidenceSnapshot,
  options: { mode: 'inventory' | 'release' }): AssetValidationResult
```

`AssetValidationResult` contains:

- `valid: boolean` and `issues: { code, assetId?, path? }[]`;
- integer nonnegative `counts`: `characterModels`, `props`, `interactiveProps`,
  `roomsWithImageSet`, `sceneLayers`, `portraits`, `illustrations`, `music`,
  `ambience`, `effects`, `voices`.

Inventory mode permits honest empty/planned/incomplete allocations with zero
counts, and accepted legitimate partial production. Release mode checks all
specified minima, identities and distributions. An invalid accepted asset cannot
contribute its claimed accepted count. Cases specify required issue codes and
only relevant count fields; implementations may report additional genuine
issues. Valid cases require no issues. Inputs must not be mutated.

The snapshot is an explicit isolated port, never an implicit filesystem or
network capability:

- `files`: repository-relative paths to actual `Uint8Array` bytes supplied by
  the caller. Fixture bytes say SYNTHETIC and are deliberately not real media.
- `records`: normalized external review/production/rights/usage/retrieval records
  indexed by their evidence path. Corresponding JSON bytes are present in
  `files`; corrupt/missing bytes are separate negative cases. Records contain
  asset identity, subject hashes, status, actor/reviewer/date/environment and
  type-specific details. `production.details.eventId` joins production events;
  it is not inferred from a tool label or filename.
- `content.entities`: typed stable IDs, with exact text/speaker for voice lines;
  `content.uses`: independently observed asset/content/use/export bindings and
  interactive/evidence status. A manifest `usedBy` claim is not its own use proof.

Review records bind current source/export hashes. Visual records include actual
inspection methods, tool, observed paths and substantive findings. Root clarified
before implementation that an agent's actual image/browser inspection is valid
visual evidence under C11/C14/C15; an automated structure check is not. P14/V05
encode that distinction. Listening remains actual human audition on headphones
and ordinary speakers; waveform inspection cannot substitute. Owner review and
human gameplay/learning acceptance are separate and are never returned/inferred.

Rights records bind notices, tool/output terms, input permissions and subject
hashes, with actual modification/redistribution/commercial-reuse findings.
Generation/editing records preserve prompt/settings hashes and output/reference
lineage. Public retrieval records preserve a versioned public URL, archive/member
hashes, exact member, instructions and actual unauthenticated availability.
Source bytes materialized by the retrieval adapter remain ordinary checked bytes.
A private-only archive or a URL with no observed retrieval record is insufficient.

T061 owns production parsing, bounds, repository filesystem/source retrieval
adapters and CLI behavior. The pure audit checks consistency of supplied evidence;
it cannot itself reopen Blender, invoke OpenAI, hear audio, establish legal rights
or certify an owner's satisfaction. Fixtures simulate those external observations
only to test validation rules; their artificial bytes are not claimed to decode,
render or play. Do not copy the synthetic evidence into production acceptance.
