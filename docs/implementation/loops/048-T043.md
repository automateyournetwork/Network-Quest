Implemented authorized conditional writes using the real T037 Database, T038
Sessions/Security and T042 SaveValidator ports. The order is:

1. Bound and reject duplicate headers, enforce exact Origin and session-bound
   CSRF with a server-derived account, enforce the raw byte cap, UUID/mode/consent
   syntax and exactly one strong conditional header. Apply the existing account
   save limit (60/minute), including replays. Compute the exact operation hash.
2. In a short `Database::immediate` transaction, call `Sessions::within` before
   any account/key receipt lookup. Admission context alone is never sufficient.
   A retained matching receipt returns its original commit metadata and current
   summary; a mismatched fingerprint returns409 without an acknowledgement.
3. If still new, parse and validate through the supplied SaveValidator outside
   the write lock. Retain the result and decode the candidate outside the lock.
4. In a new `BEGIN IMMEDIATE`, call `Sessions::within` again, then recheck the
   receipt before using either a provisional error or a valid candidate. A receipt
   committed meanwhile wins over a now-incompatible new-write policy.
5. For a new valid candidate, check explicitly configured stored-version support,
   current preferences, same-adventure/manual adoption and replacement consent,
   then the reviewed condition. Write the single row and successful receipt
   atomically. The callback's result is not returned until Database commits.

There is no unconditional upsert. Empty creation uses `If-None-Match:*` and
revision1; replacement requires the exact reviewed `If-Match:"save-N"` and updates
with an additional SQL revision predicate. Revisions are bounded to JavaScript's
exact integer range; attempting to increment its maximum fails without mutation.
Missing preferences fail503; saves never create preferences or enable autosave.
Automatic saving requires current opt-in and an existing same-adventure slot.
Manual replacement of another adventure requires the exact `true` header bound
to that operation's payload and condition. Conflicts return the current summary.

Snapshot JSON is stored exactly as received, including whitespace, escape
spelling and UUID case. Payload hash covers those bytes. The DB's generated
`acknowledgement_json` contains only immutable request/revision/time metadata;
the repository never inserts into that column or puts another snapshot in a
receipt. A replay can acknowledge revision8 while current summary/ETag are9.
Summary projection includes only public contract fields; authoritative current
revision/time/version/adventure columns override duplicated display metadata.
Malformed display metadata fails closed without exposing a partial summary.

Receipt retention is exactly604800 seconds: `now < expires_at` is retained;
`now >= expires_at` is expired, even before cleanup runs. An expired key does not
bypass stale If-Match. A new valid operation using an expired key removes only
that key's expired row in the same successful transaction; failed operations do
not prune receipts. Other cleanup remains T165.

## API and policy handoff for T044

All types live in the single owned source file; no helper or autoload changes.

```php
new SaveRepository(
    Database $database,
    Sessions $sessions,
    Security $security,
    SaveValidator $validator,
    array $replaceableVersions,
    ?callable $clock = null,
    ?callable $phaseObserver = null,
    string $route = '/arcade/play/network-quest/api/v1/save',
);

$result = $repository->write(
    string $peerAddress, // trusted socket REMOTE_ADDR
    array $fields,      // raw [name,value] pairs, preserving duplicates
    string $rawBody,    // exact bounded bytes
);
```

The route value is trusted deployment configuration, never an arbitrary request
path. This port performs exclusively PUT. T044 must route exact paths/methods,
reject query selectors, enforce JSON media type and transport slow-client/header
limits before buffering, and use the existing `Security::readBody` for bounded
stream reads/content length/framing. Preserve duplicates upstream when the SAPI
would otherwise discard them. The repository repeats fixed string/header guards.
Do not double-apply the account save quota in T044. The existing save limiter has
an account dimension; source limits for auth/deletion remain their own policies.
Never obtain a rate source from arbitrary forwarded headers.

`SaveWriteResult` is readonly and contains `status`, `code`, `message`,
`acknowledgement`, `currentSummary` and `etag`. Success is201 for creation or200
for replacement/replay. Fixed problems cover400 invalid JSON,409 operation or
adoption policy,412 conflict,422 invalid/unsupported save and428 missing condition.
Fixed admission failures remain `RequestRejected`. Storage/busy/observer exceptions
propagate without any successful result; T044 maps them through `Security::problem`
to the fixed503 with Retry-After. Do not expose exception messages, SQL or requests.
For returned problem results, T044 supplies its server correlation UUID; it must
not treat the idempotency key as an arbitrary error echo. Return no-store headers
and current ETag, and serialize only the appropriate acknowledgement/Problem/
Conflict shape. No GET or preference route is implemented by this task.

`replaceableVersions` is required trusted configuration: a list of pairs with
integer `saveSchemaVersion` and string `contentVersion`. It describes which stored
versions the release can safely read/migrate/replace, independently from today's
new-write validator policies. An empty list blocks replacement. Unknown future
stored versions remain intact; retained receipts still resolve before this check.
Old readable versions may remain replaceable after they cease being writable as
new candidates. T044 must supply the reviewed actual release policy and version
pairs; no synthetic test policy is production configuration.

Coordinator approved two explicit UUID choices. Idempotency keys are opaque,
case-sensitive validated UUID **spellings**, consistent with SQLite BINARY
comparison. Uppercase is valid and acknowledged exactly; changing only key case
is a different key, subject to normal policy/preconditions. Adventure identity
comparison ignores UUID hex case, while snapshot, summary, stored adventure ID
and fingerprint bytes preserve original spelling. There is no normalization.

The fingerprint format is SHA-256 over eight length-prefixed byte strings:
`NetworkQuest/save-fingerprint/v1`, method, exact route, mode, confirmation
(absent is empty), conditional-header name, exact conditional value and raw body.
Each prefix is a four-byte unsigned network-order length. Empty confirmation is
not an accepted header, so it cannot alias a permitted explicit value. Cookie,
CSRF, server time and request key are excluded; account/key already scopes the
receipt. Same-account reauthentication can replay identical operation bytes.

Coordinator also approved the optional trusted phase observer for controlled
test interleavings. It receives only fixed `admitted` / `validated` strings,
outside transactions, no request/context/token/payload values, and its return
cannot affect validation or authorization. It defaults absent and must never be
wired from HTTP input, runtime configuration or a test-auth flag. Exceptions
abort without partial slot/receipt state. It is not an authentication bypass.
