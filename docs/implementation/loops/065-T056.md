for these narrow private CLI additions: synthetic independent Google session,

unsupported historical bytes, and pending/expired deletion ledger setup. A bounded

receipt-status results. It forwards only the fixture's exact origin and four
fixed method/path combinations using the fixture's own CA. No production identity
or private provider configuration was read. Existing T050/T052 fixture methods
remain available.

The final SAVE02 case closes the actual Firefox persistent context/browser and
reopens its isolated trusted profile twice. It then installs a new synthetic
provider session and restores each account independently, including room, notes,
kit presence/absence and unchanged stored snapshot. This is browser-process return
evidence with synthetic identities, never a real OAuth return or physical
cross-device result.

SAVE07 holds the losing tab's real PUT after its GET captured the old revision,
lets the other tab commit, then releases the stale conditional request. SAVE08
commits a real PUT while dropping its response, advances the slot from another
tab, and retries the frozen older operation. Logout cases deliberately select
both committed-before-revocation and arriving-after-revocation orderings.

Deletion cases separate actual completed DELETE/receipt from prepared pending and
expired ledger states. Unknown status with an expired session, receipt loss on
reload and a delayed old completed response after another account starts its own
adventure remain unconfirmed or ignored as appropriate. Native tamper cases send
an ownership field, unsupported new-write content and 262145-byte body through
actual browser requests and verify both synthetic account slots remain unchanged.
