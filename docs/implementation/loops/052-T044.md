## Result and interface

Implemented `server/src/Routes/Save.php` and `Routes/Preferences.php`. Both expose
the T041-agreed raw port:

```php
handle(string $method, string $route, string $rawQuery,
       array $rawHeaders, mixed $bodyStream, string $peerAddress): array
```

The return shape is `{status, headers, body}`. Relative route is `/save` or
`/preferences`. The shared transport owns TLS/Host/path admission, upstream
duplicate-header/slow-client controls and routing. Raw headers retain repeated
field pairs; handlers use Security::headers/readBody/peerAddress. No normalized
SAPI array is represented as proof that duplicates did not arrive. The tests call
the actual route classes, including in independent overlapping PHP processes;
**these results are not live HTTP/SAPI, browser or real-provider acceptance**.
T041/root owns Router/configuration/transport integration.

Constructors:

```php
new Save($database, $sessions, $security, $repository, $accountAccess);
new Preferences($database, $sessions, $security, $accountAccess);
```

Use the same game Database, Sessions, Security and mandatory RecoveryAccountAccess
through the trusted composition. SaveRepository's T045 signature requires that
barrier immediately after its explicit replaceableVersions argument. PUT has no
outer AccountAccess wrapper: repository admission, initial receipt and final
transaction own their separate barriers, leaving semantic validation outside.
The route does not apply the save rate limit a second time.

GET acquires the external recovery barrier before session admission and its short
transaction, then uses Sessions::within at the final read. It reads only the
session-owned account, returns 404 for its empty slot, and returns fixed public
summary metadata plus the stored JSON. The summary's revision/time/version come
from server columns. Snapshot bytes are preserved directly, including unknown
future fields, empty objects and integers too large for PHP numeric round trips.
UTF-8 and the stored payload hash are checked; current new-write policy, reset and
migration are absent. Unsupported newer data is preserved for client version
dispatch. No query account selector or alternative method is honored.

PUT requires JSON media type and bounded stream framing (262144 actual bytes),
then passes exact bytes and raw header pairs to the accepted repository. It maps
the repository's 200/201 acknowledgement, 409/412/422/428 fixed problems and current
ETag without confusing an older committed receipt with today's slot revision.
Only a 412 includes currentSummary, including null for an empty owned slot.
Security exceptions provide fixed 400/401/403/413/429/503 responses. Unexpected
storage/recovery errors become generic 503/Retry-After; no SQL or request text is
echoed. Every success and failure is no-store.

PATCH authenticates exact Origin/CSRF and account ownership, charges the existing
preferences rate policy once, and requires one exact strong `"prefs-N"` If-Match.
It rejects If-None-Match, weak/list/wildcard/overflow/leading-zero conditions.
At least one of the seven contract settings is required. A small 4096-byte stream
cap bounds this flat scalar object; invalid fields, types, values, duplicate keys
(including escaped aliases), malformed JSON and nonfinite numbers fail without
coercion/default insertion/truncation. Only supplied fixed-map columns are bound
in prepared SQL. A short final transaction rechecks session/account and the
reviewed preference revision; one winner advances it, another sees 412. Missing
preferences never recreate defaults. Neither success nor failure writes a save
or save receipt. Successful responses contain all current values and their ETag.
