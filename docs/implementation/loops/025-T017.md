## Action contract

`SemanticAction` is an intent-only union: select a verb, open/close a panel,
interact with an identified target using a verb/optional item, or inspect identified
evidence. Runtime shape checking rejects unknown intent fields, including
renderer-supplied effects. Domain registry membership and eligibility remain
trusted domain/content checks.

`ActionDispatcher` is the restricted renderer port:

```ts
capture(input: SemanticAction, expectedContext?: ActionContext | null): CapturedAction;
captureScope(expectedContext?: ActionContext | null): ActionCapture;
dispatch(action: CapturedAction): ActionResult;
cancel(action: CapturedAction): boolean;
```

`ActionContext` carries adventure ID, configuration revision and attempt ID.
`CapturedAction` is frozen, has a fresh UUID and detached intent/context, and is
owned by exactly one bus. Dispatching a copied/forged envelope fails. Re-delivery
of the same object returns its retained receipt without rerunning a handler or
announcing again. That receipt describes the earlier action, not current world
state. WeakMap ownership allows receipts to be collected with their commands.

`captureScope` binds one projection's context and bus epoch; each activation gets
a new command ID within that scope. Capture the command before deferring an
animation/input callback, then dispatch that same object or cancel it. A scope
retains its original epoch even if a command is minted after invalidation.
Application code calls `invalidate()` for restore/logout/title/reset or another
runtime replacement, including replacement with the same world versions.

Application-owned handlers resolve synchronously and purely, optionally returning
a synchronous commit plan. The bus rechecks cancellation, context, epoch,
disposal and exact registration ownership between resolution and commitment.
There is no implicit queue: reentrant dispatch returns busy without consuming
its command; the caller may explicitly retry afterward. Handler, observer and
error-reporter exceptions cannot leave the bus stuck or suppress other surviving
observers. Promise results fail closed and rejected Promises are observed rather
than leaking unhandled rejections. Canceling a committed synchronous action is
not an undo operation.

`reducerActionHandler` is the clean integration adapter. A trusted pure resolver
selects `ReducerInput` from intent and current reducer state; the adapter detaches
the resolved command, carries the original identity/versions into the real
reducer, and commits through an atomic compare-and-set port. Missing adventures,
unsupported routes, reducer rejections and replaced stores do not commit. The
renderer never supplies authoritative effects. This does not implement later
navigation policy, scoring, dialogue or account behavior.

## DOM shell

`createAppShell(host, bus)` returns the owned shell element, a visual-only
`presentationHost`, a separately owned future-panel mount, `render`, and
`dispose`. It consumes supplied `AppShellView` controls, object/exit descriptions,
evidence with source/freshness, captions and honest presentation status. It has no
authored episode content or independent progress state. Main bootstrap remains
unchanged and honestly says play is unavailable. Integrating application code
must import `app-shell.css` when it mounts this shell.

Native buttons unify pointer, pen/touch click and Enter/Space. Visible supplied
verb/panel buttons expose W/L/T/U/I/N/C/Escape equivalents. Tab retains native
navigation; arrows/Home/End move within control groups. Shortcuts are scoped to
the focused shell and suppressed in editable fields, composition, repeated key
events, conflicting modifiers and previously handled events. Unavailable controls
remain discoverable/focusable with their visible reason and `aria-disabled`;
activation explains the reason without dispatching. Missing handlers provide
honest unavailable feedback.

Keyed DOM updates retain focus and existing panel edits, restore removed-control
focus to the title, and never focus-steal from outside the shell. All supplied
text uses `textContent`, including captions and evidence. One polite action
status suppresses identical repeated messages; large scene changes and captions
are not live-region floods. CSS has visible focus, 44px minimum buttons, wrapping
groups and a single-column narrow layout, without essential hover behavior or
animation. Disposal removes only owned listeners/subscription/DOM and does not
dispose the shared bus or another module's state.

### Shared T018 projection scope

`AppShell.render(view, capture?: ActionCapture)` accepts the original capture
scope for status/media-only updates. A direct authoritative render can create a
fresh scope; a room renderer must forward its existing scope through loading,
ready, failure, retry and mode changes. T018 coordinated `onView(view, capture)`
and binds a new scope only when a new authoritative projection is supplied.

Two concrete regressions were observed before correction:

1. Removing and re-registering the same handler function during resolution could
   authorize the old commit. Registrations now have distinct identity objects.
2. A same-version restore plus `bus.invalidate()` still allowed clicks in the old
   shell because click-time capture minted a new epoch. The browser regression
   observed `Fixture action received` instead of stale feedback. Shared capture
   scopes now reject old controls, including a later media-ready status render,
   until an authoritative new projection is supplied.
