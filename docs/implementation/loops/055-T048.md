## Implementation and interface

- `captureSafeSnapshot(state: ReducerState, validator: SaveValidator)` captures the supplied actual state synchronously, rejects pending reducer transitions and every unsafe runtime activity, then delegates durable-field projection and authored-anchor/reference/safety validation to the accepted validator. The successful capture owns a deep-frozen snapshot, frozen exact UTF-8 byte array, opaque captured dirty generation and account generation. It never substitutes a preparation checkpoint or previous safe capture for an unsafe current state.
- `advanceDirtyGeneration(DirtyGeneration)` is bounded arithmetic only. Existing reducer changes already increment their generation; callers must not increment again after reduction or during capture. `acknowledgeCapturedGeneration(runtime, capture)` projects counters only, requires the same adventure UUID (case-insensitive) and account generation, rejects invalid/regressed counters and preserves a newer acknowledgement. It does not set Saved, verify receipts or reconcile server slots. T049 must verify matching request/receipt ownership and invalidate pending operations on restore/new-run/account changes before calling it.
- `SaveReader({currentContentVersion, readPolicies, migrations}).read(Uint8Array, signal?)` retains an owned immutable original byte array on every result. It bounds UTF-8/JSON decoding, dispatches schema versions before interpreting v1 fields, validates a supported stored version under its explicitly provided historical policy, applies an unambiguous acyclic migration chain and validates each target. Non-ready results disable replacement/autosave and never expose a partially migrated candidate. A pre-aborted signal returns interrupted; execution is synchronous and has no asynchronous commit window.
- Declarative migration maps change qualified reference fields only. They cannot edit notes, hypothesis prose, conclusions, attempt/event UUIDs or opaque flag values by accidental string replacement. Explicit safe relocations require an explanation and physical-configuration invalidation. A changed configuration advances beyond all retained measurement revisions, stales measurements while preserving their original attempts/readings/revisions, and fails at the schema ceiling. Many-to-one flag mappings fail rather than silently losing a flag. Target policy catches invalid references, unsafe anchors and collection collisions.
- T047 owns the exact GET `snapshotJson` lexical slice. T049 feeds `new TextEncoder().encode(result.snapshotJson)` to the reader; it must never stringify an unknown parsed snapshot. The reader does not consume the API envelope or modify account/API/UI composition.
- T036's 0.9.0→1.0.0 baseline remains explicitly hypothetical. Its literal input and independently authored expected result were not edited. Tests supply declared fixture-only policies/maps; runtime imports no fixture and registers no production legacy migration. The actual current introduction read policy is separately exercised and rejects fixture IDs and metadata-only rooms.
