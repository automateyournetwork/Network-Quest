## Implementation

`src/main.ts` now mounts the real application in `src/app/application.ts`.
`src/app/content.ts` loads an explicit list of public authored JSON documents and
validates the full registry before any controller or adventure starts. Future
room metadata does not create playable rooms. `src/app/adventure.ts` constructs
a fresh empty R01 world with random adventure/attempt IDs, the authored safe entry,
empty inventory/journal/objectives and autosave off. It never imports the example
save. It preserves a supplied authenticated identity and confirmed slot metadata
without issuing a request; the actual application starts as a guest.

`src/app/introduction.ts` supplies explicit hotspot/effect policies and deduplicates
only identical canonical bindings. Photon and the satchel share the existing kit
flag receipt. Notebook, dialogue, inventory and navigation use their actual ports.
R01/R01.entry and R02/R02.entry are explicitly bound with stable-exploration;
navigation supplies the reducer recovery policy and equivalent scene projection.
Controller listeners precede the application render subscriber. Store CAS swaps
state only, so dialogue can finish its transient history before rendering.

`src/state/tutorial.ts` wraps the canonical reducer. On a successful changed safe
candidate, it checks actual retained evidence plus authored typed conditions,
then applies each exact complete objective batch through the same canonical
reducer before the controller performs its one CAS. A failed objective reduction
returns the original state and rejection, rolling back the initiating operation.
No bus subscriber dispatches reentrantly, no renderer grants rewards, and no
intermediate candidate is rendered, saved or installed. Internal UUID commands
may advance the dirty counter more than once in that single atomic installation;
the coordinator explicitly approved this composition.

O01 requires separate power/link fact IDs and an actual current PHY04 inspection
from R01 with PR003/PROFILE-COPPER-100 provenance. A valid 105 m over-limit
observation earns the inspection lesson while retaining its incorrect physical
result and limited scope. Completion changes no physical revision and never
relabels the observation. O02 requires O01, the four actual endpoint/path facts,
authored flag conditions and a nonempty bounded pinned hypothesis about the
authored scope. No word or diagnosis is graded. Objective receipts prevent repeats.
The shell projects actual notebook evidence and authored completion explanations.

`src/ui/title.ts` offers New Adventure, Continue, Settings and Credits, plus Save
during play. Continue is visibly unavailable because account restore is not
connected. Settings/credits describe the present capability honestly. New Adventure
warns before discarding memory or encountering an existing/unknown authenticated
slot, checks that the reviewed state is still current, and preserves exact state
on cancellation. Confirming creates memory only, clears replacement consent,
disables autosave and retains confirmed slot metadata. Unresolved save/auth
operations cannot be discarded through this entry point. Controlled metadata
doubles in tests are explicitly not OAuth evidence.

The sign-in invitation appears after O02 when the notebook/dialogue is closed.
Google/GitHub are labeled unavailable; no fake provider, account or saved claim is
created. Continue as guest dismisses it for this adventure and changes no game,
identity or slot. Explicit Save may offer it again. Starting anew invalidates bus,
notebook and dialogue captures, disposes old passive game views, clears old status
and editor DOM, and moves focus to the new room heading. Status-only redraws retain
the original authoritative capture. No browser persistence, server write, API key,
live provider, runtime AI or production credential is used.
