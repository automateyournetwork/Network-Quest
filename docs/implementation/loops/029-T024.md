## Behavior and integration interface

`evaluateCopper(challenge, action, relevantWorld)` uses the existing
`Evaluator<Challenge, Input, WorldVersion, Observation, never>` contract.
`action` is the existing `DomainAction` with an action ID, captured configuration
revision and attempt ID. Inputs are `measure-length`, `test-continuity`, or the
narrow `add-repeater` counterexample. No accepted effects are produced by this
slice. Reducers remain responsible for eventual atomic objective effects and their
own freshness recheck.

The challenge is either:

```text
{kind: "copper-length", profile, lengths: [{value, unit: "m"}, ...]}
{kind: "copper-continuity", profile, requiredConductors: [true, false, ...]}
```

`profile` projects existing content fields `id` and
`parameters.{maximumChannelLength,inclusiveMaximum}`. The caller supplies the
reviewed parameters; missing, altered or unknown profiles are rejected. The only
implemented identity declares exactly 100 m inclusive. This is a fictional profile,
not a universal copper/Ethernet limit. Full content source claims/model prose still
belong to existing content validation.

The caller binds current path facts to the same captured world generation. A fresh
continuity test evaluates supplied post-repair facts; choosing a repair never makes
those facts true automatically. Observations include only the copied configuration
revision and attempt ID, not other fields from a structurally wider world object.

Length results retain metre units, total, maximum, headroom/excess, `scope: "length
only"` and `wholeRouteProven: false`. 85 + 10 = 95 with 5 m headroom; 95 + 10 = 105
with 5 m excess. Decimal quantities are added/compared at a common exact decimal
scale before conversion to finite numeric readings; displayed rounding cannot turn
an over-limit path into success. Zero is allowed; negative/nonfinite/missing/wrong
units, empty paths, sparse arrays and unrepresentable totals fail as author errors.

Continuity results retain open-conductor indexes and an explicitly limited scope.
An added repeater leaves an existing open disconnected. Adding one to an intact
path is not scored as a valid regeneration design. Unreviewed regenerative challenge
models fail closed. No compatibility, powered-segment design, complete route or
service-restoration success is inferred from either predicate.

Malformed author data is checked before learner input and stale command captures.
It returns `content-error`, a readable field/issue diagnostic, zero penalty/progress
and no effects. Missing/malformed learner actions return `invalid-input`; old
configuration/attempt captures return `invalid-input / stale-action`. These are
command guards, not implementation of T13's later stale-measurement proof rule.

`evaluateAuthoredQuantity(value, "dB", "passiveLoss")` executes T14's generic
nonnegative-unit guard without implementing optical scoring. A valid quantity only
reports authored-data validity. Copper uses the same quantity guard for metres.
Every returned result is detached data; there is no DOM, network, persistence,
randomness, renderer award or dependency on fixture expected answers.
