## Interface for T015 and later authors

1. Compile the root schema using installed `ajv/dist/2020.js` and `ajv-formats`.
   `$id` is a schema identity under a reserved `.example` domain, not a fetch
   requirement. Load the actual schema locally. The root accepts `kind: world`,
   one authored record, or `kind: collection` with a nonempty `records` array.
   Common document fields are `schemaVersion`, `episodeId`, `contentVersion` and
   `kind`; `$schema` is optional. Definitions can also be addressed directly with
   `#/$defs/room`, `#/$defs/objective`, etc.
2. `world.documents` lists only existing authored records by `kind`, qualified
   `id` and repository-relative `path`. A collection file can be listed for more
   than one record; resolve the specified record by kind/id and check envelope
   versions. The empty list is deliberate during foundation. World metadata and
   actual authored records have different definitions; metadata cannot pass as a
   room/objective/character document. Do not require unlisted future scenes to
   validate this initial registry or treat metadata completeness as release proof.
3. `world.reviewedRegistry` maps unchanged reviewed `Sxx`, `PHYxx`, `STATExx`
   identities to their `spec001:` runtime IDs. The seven already qualified profile
   IDs remain unchanged. Read `content/spec001/sources.json` as its existing review
   format, **not** as a content document. It remains the model/case authority.
   Objective rule/profile references were derived from that review's existing
   objective associations; no cases or thresholds are duplicated in world.json.
4. The runtime `quantity` definition has exactly T012/save-v1's ten units. The
   separate source parameter definition also preserves reviewed `Mb/s` and
   `toy-level`. Neither label becomes a valid persisted reading unit. Source
   `Mb/s` needs an explicit reviewed conversion to runtime `Mbps`; toy-level is a
   toy symbol code, not volts. Parameter-tree integers are dimensionless counts
   or codes; physical quantities require a value/unit pair. T015 must compare
   authored profile parameters/model claims with their reviewed record.
5. T015 owns identity uniqueness and original/qualified suffix agreement, referenced
   record existence and kind, declared-vs-used facts/items/flags/abilities,
   profile/source agreement and dimensional checks, bounded prerequisite traversal,
   impossible cycles, all three independent paths, optional/future dependencies,
   dialogue reachability, equivalent solutions, essential-item recovery and safe
   geometry when actual rooms exist. `condition` nodes are discriminated data
   (`all`, `any`, `objective-complete`, etc.), never executable scripts. Full-object
   JSON uniqueness is not uniqueness by ID. Generic syntactically valid unknown
   IDs must still fail registry lookup.
6. Room catalog safe positions are semantic allowlist anchors, distinct from the
   authored room's mapping to a walk region and point. Both must agree before a
   scene is playable. Snapshot eligibility, stale measurements, shutdown exclusion
   and transactional persistence remain owned by the existing save contract and
   later state/persistence work; this schema does not duplicate that schema.
