## Behavior implemented

The shared schema/registry/loader admits only the reviewed MG02 payload. Its
actual R06 budget-abacus entry stays disabled with a plain fiber-verification
explanation until O06 is complete. Controller start independently enforces that
prerequisite. The panel opens with keyboard focus inside the existing adventure
frame and exposes untimed practice, full diagnosis, hints, explanations, boundary,
compatibility, retry and exit. No frame, modal ownership or iframe protections
were replaced.

The new optical adapter is the reviewed proposal joined into production source.
It calls the existing `evaluateOptics` for all physical calculations and exact
compatibility cards. T04 is practice, T05 the full diagnosis and T15 the inclusive
reserve comparison. Correctly diagnosing T05 keeps its physical result failed:
−13 dBm receive, 1 dB margin, reserve shortfall and no overload. The old T092
source fixtures, actual evaluator and profiles remain byte-identical. No second
optical calculator, invented component losses, repair, main objective, item or
score is introduced.

Captured intents contain only signed unit-tagged predictions and separate
reserve/overload choices. The bus deep-copies these finite bounded values and
rejects extra authority fields, malformed units, nonnumbers, enum coercion and
out-of-range input. Blank UI fields become explicit missing input, never zero.
The contained form accepts decimal and negative predictions, labels units, and
keeps reserve and overload separate. The current UI preserves its same-session
draft through help updates and retires detached callbacks.

Actual full completion selects only the own fact plus minigame achievement
batch. The inherited reviewed finalizer advances only that activity's confirmed
receipt in its captured Retry preparation. Equipment, required tools, unrelated
progress and route stay at entry values; notes, facts and assistance remain
retained learning. Raw physical/diagnosis observations have no award effects.
Practice, boundary and compatibility explanations record worked help; corrective
full answers record solution help before display. Capacity rejection is atomic.

Save-v1 shape and receipt-first server policy remain unchanged. Actual earned
safe snapshots after exit pass JavaScript and PHP validation; seven cases agree
on valid completion/help and invalid objective/quest aliases, unknown minigame
achievement or misbound help. Active sessions cannot be saved. Reconstructed
local runtime replay retains its existing achievement without a transient
session. No provider, remote account transport or production save claim follows.

The shared dispatch and sample projection explicitly name toy-message,
toy-loom, power-audit and optical-bench variants. There is no generic non-power
fallback to the decoder. Existing toy/power/MG01 regression checks remain green.
