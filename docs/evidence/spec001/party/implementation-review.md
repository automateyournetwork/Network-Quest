## Behavior and ownership

`src/state/party.ts` owns the exact nine optional allies. Invitation requires an
actual discovered actor, its authored home room, the authored eligibility condition,
and a canonical accepted measurement with exact composite objective provenance.
CH16 uses O05 and the OPTICAL profile, not O09's incomplete market checks. Walking
home may make that record stale: it remains learning history and never current
repair proof. A completed-objective fact or an already-complete response is not a
measurement. No optional ally or quest gates a conventional main path.

`objective-history.ts` checks available stored provenance, conclusion, names, units
and arithmetic using the existing reviewed profiles and physical evaluators. It
never reconstructs an old world from current flags. O05's saved summary omits the
individual compatibility fields, and other summaries omit some predicates. The
accepted conclusion remains within the existing validated-snapshot trust boundary;
there is no claim of cryptographic attestation or proof against a fabricated but
coherent snapshot. These historical checks never accept a current repair.

An explicit post-recruit practice session records its start, existing measurement
IDs and narrow observations while new canonical objective measurements execute.
Photon/Hermit require an actual failed compatibility field after inspection and
cleaning, followed by the inspected matching configuration. Missing cleaning alone
cannot pass. Echo requires actual wrong then correct repeater claims; an open
conductor alone cannot pass its lesson. Other lessons use actual copper continuity,
optical loss/bounds, radio noise, delivered allocation or capability comparisons.
Hydra's explicit modes review accompanies a new optical result and invents no
multimode physics. Advanced explanations expose actual supplied fields or recorded
checked quantities, with current/stale labels and distinct technical limits.

Practice is runtime control state. Restore/new adventure/confirmed logout replace
that state; Retry/E03 Continue explicitly clear it. Completed levels and exact
cumulative abilities use the existing RecruitProgress shape. No XP, grind counter,
new save field, renderer verdict, automatic score or hidden persistent receipt was
added. Canceled logout retains the existing unchanged-state semantics.

Up to two distinct recruited allies can be active. Safe preparation/exploration
swaps cost nothing and use the ordinary configuration revision, measurement
staleness and dirty generation behavior. Party work never broadens the committed
encounter admission policy. All 18 earned ability definitions, including every
authored action reference, delegate to existing canonical bench operations with the
same current conditions, held-kit requirements, measurements and effects. Hydra's
profile action is an authored empty-effect context read at the optical bench; its
explanation has no physical, objective or progression effect.

Discovery uses actual hotspot.subjectId, room.characterIds and authored discovery
rooms. New Adventure includes the validated CH01 encounter in its single install.
CH25 has a real safe R11 Look/Talk actor hotspot. Look never triggers a hazard or
repair. Bound actor evidence effects and the existing Photon/Titan dialogue stage
discovery before their one store CAS; failure installs neither half. There is no
name mapping, duplicate dialogue handler or automatic room-entry sweep.

The separate party panel is inside the accepted adventure frame. Native buttons,
Escape, captured intents and detached inactive controls preserve the existing
interaction model. Its enlarged-reading Game/Close controls stay in flow, scoped to
`.nq-party`. Compendium and notebook remain worker107's read-only integration.

## Save policy

The public save-v1 schema is unchanged. Trusted generated policy now declares the
exact cumulative `abilityIdsByLevel` relationship for each recruit. JS and PHP new
write checks reject missing level metadata, unearned/foreign abilities, missing
required unlocks, duplicates and unauthored levels. Generator validation rejects
empty, repeated, skipped or foreign unlock definitions. Original fixture JSON and
migration files were not altered; old fixture accessors project explicit trusted
level maps. SaveRepository receipt-first/replay/transaction code is unchanged.
