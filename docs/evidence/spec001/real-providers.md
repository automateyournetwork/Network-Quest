## Two-device session

Use only the game and provider controls. In an adventure, **Game** opens Save, Restore Save and Settings. **Notebook → Personal notes** accepts a synthetic marker. Close the notebook before continuing. At the title **Continue** loads the account slot when the session is authenticated. At a fresh guest title, use **New Adventure → Game → Save** to reach the providers. If sign-in offers an existing slot, **Cancel** retains the starter adventure. Reload the game in the same now-authenticated profile to reach title **Continue**, or explicitly choose **Load Existing Save → Discard current progress and load** in the adventure. [Title and invitation](../../../src/ui/title.ts) · [Save choices](../../../src/ui/save-dialogs.ts) · [Frame navigation](../../../src/ui/adventure-frame.ts)

1. **Preserve the guest on A, once per provider.** In the Arrival Lift, talk to Photon the Firefly, finish or skip the dialogue, and check the inspection kit, Photon clue and a synthetic note. Open Save and choose the provider. With a test identity that can see a consent choice, decline at the real provider. Record the canceled callback outcome, return focus to the game, and use **Check Session** if offered. Separately close a newly opened sign-in window before completing it, then check the session or choose **Cancel sign-in**. In each case verify Guest, the original room/kit/clue/note, and absence of a save acknowledgement. A provider that never offered denial leaves that observation open. [Callback and session behavior](../../../server/src/Routes/Auth.php)
2. **Recover a blocked popup on A, once per provider.** Use a browser's per-site control or a controlled browser policy that actually blocks the user-initiated popup. Record the blocker/browser and the visible blocked message. Select **Open Sign-in Tab**. If the browser also blocks that action, preserve this result and use a site exception in the test profile before retrying the separate-tab action. Complete authorization in the separate tab. Check the session in the retained game tab and confirm its guest progress survives. Close or cancel the first-save offer without writing. Use confirmed game logout or a clean profile before the next guest/provider trial. Restore the profile's original popup setting after the attempt. Record separate observations for block and successful fallback. [Popup and manual recovery](../../../src/services/account.ts)
3. **Establish distinguishable slots on A.** Use separate clean runs with autosave off. Give G the Arrival Lift, an empty inventory, no Photon clue and note `G-lift`. Give H the Titan's Workshop after speaking to Photon, with the inspection kit, clue and note `H-kit`. Read the consent disclosure on each fresh grant. Stop on an unexpected permission or account. After the game recognizes the chosen provider, confirm the empty slot using **Save this adventure**. Observe **Saved at**. Record the provider, marker, room, kit/clue and revision when the review shows it. If either account starts with a slot, cancel and select an agreed empty test account. [One-slot examples](../../../tests/e2e/single-save.spec.ts)
4. **Quit and return on A; restore independently on B.** For each provider, quit the browser completely after the acknowledged save. Relaunch with a clean test profile or a new private session after all private windows close. Authenticate with the same real provider account and use title Continue. Verify the entire marker/room/kit/clue combination. Then repeat on physical B using a fresh session, with no transfer of a profile, cookies, files or browser sync. On each device switch from G to H or H to G via confirmed game logout and select the intended provider account. Confirm that only the selected account's marker and inventory return. An unknown or other-account slot fails isolation. [Account ownership](../../../server/src/Routes/Auth.php)
5. **Exercise the one-slot choice and cross-device conflict.** In the same provider account with its confirmed slot loaded on A, start a different adventure on B, add a disposable marker and use Save. Check that cancel preserves the B adventure and A's original slot. Reopen **Replace With This Adventure** on B and leave the final **Confirm replacement** prompt open. On A update the marker and save, waiting for acknowledgement. Now confirm the stale review on B. Expect **The server save changed**, followed by **Keep Playing Without Saving** preserving B's marker. Use **Restore Save → Discard current progress and load** to load A's newer marker on B. For SAVE03's successful replacement, repeat against the current revision without an intervening write, using a designated disposable run. Confirm A can now restore that exact replacement and the other provider still has its own slot. Record the actual revisions for both providers. [Replacement and revision preconditions](../../../src/services/save-coordinator.ts)
6. **Return after expiry and logout.** On A, keep an unsaved synthetic edit after a confirmed save. Allow the test game session to expire normally (two hours without game-service activity or 24 hours absolute in the inspected build). Save, check the honest status, and reauthenticate using the account offered by the recovery UI. Verify the unsaved marker persists until explicit discard, and the prior acknowledged slot can still be read on B. Separately, make an unsaved edit, choose **Settings → Log out → Cancel**, and confirm the editor and identity persist. Then **Log out → Confirm logout**, verify the title clears the adventure, sign in again, and restore only the acknowledged marker. [Session lifetimes](../../../server/src/Sessions.php) · [Real-provider portions of SAVE09/13](acceptance-matrix.md#one-slot-regression)
7. **Record purpose-specific reauthentication separately for SAVE12.** After the slot/isolation evidence is complete, use only designated disposable game accounts whose owners consent to removing their test saves. **Settings → Delete account → Confirm choice and sign in again** opens a new real provider roundtrip. Check that the same original provider account completes it. The ready UI alone does not establish that the server accepted the deletion proof. Only on explicit operator confirmation for this disposable account, choose **Delete account now** and record the confirmed result. If confirmation was lost, use the operation's **Check deletion status** and record its actual disposition. A guest session, a pending status or an expired receipt leaves deletion unconfirmed. Confirm the other provider's surviving slot before repeating with that provider's disposable account. Preserve the separate hosted backup-expiry requirement.
